# Task: 长程结构查询对照基准（P69）

**状态**: 设计中
**方豆方向 (2026-11-05)**: 重点比较“源代码上很远、连接结构上很近”的信息查询/提取，
同时评估准确度和成本。

## 目标

不是比较“功能列表”，而是比较**信息获取策略**：

- 源码阅读/LLM 推理能拿到什么；
- 词法搜索/符号索引能拿到什么；
- sv_query 的结构查询能拿到什么；
- agent + sv_query 的端到端准确率/成本是否更好。

## 子项

- P69.1 对比矩阵/任务定义/评分协议（设计文档）
- P69.2 12–15 个 pilot 任务 + 冻结 ground truth
- P69.3 B0/B1/T1/T2 harness + 原始记录
- P69.4 准确率/成本报告（含失败与置信错误）

## 边界

- 先做查询/提取，不做故障修复；
- 不自评：ground truth 必须双来源 + 冻结；
- 不把“直接查询正确”当成“agent 产品有效”；
- HWE/VeriBug 修复对照仍是后续阶段。
