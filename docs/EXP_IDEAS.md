# exp 创意清单（未落地的想法）

> **性质**: 想法 backlog —— 只记「想法」和「它要解决的问题场景」。
> **现状**: 这些能力**未落地**（无真实项目验证 / 算法不可靠 / 语义未定稿），
> 已从 CLI 整体移除，实现代码归档在 `docs/archive/2026-10-20-exp-attic/`（可随时取回参考）。
> **将来**: 逐个重新设计重做，而不是把旧代码搬回来。

| # | 想法 | 解决什么问题 |
|---|---|---|
| 1 | **自动识别总线协议**（AXI4 / AXI4-Stream / APB / AHB / Wishbone / TileLink-UL），并给出协议的结构语义 | 拿到别人的 RTL，先要知道"这根总线是什么协议、有几个通道、字段怎么摆"，才能问对问题 |
| 2 | **识别 valid/ready 握手对**，判定每对是哪种握手语义（ready 先给 / valid 先给 / 同时 / 依赖型） | 握手协议错是最常见的接口 bug；人工要沿连线逐个核对，容易漏 |
| 3 | **反压拓扑与死锁候选检测** | 多级流水/总线的反压环路会造成"全部停住"；静态找出可能的环，比跑仿真撞死锁便宜 |
| 4 | **SVA 断言抽取与断言覆盖评估** | 想知道"哪些关键信号其实没有任何断言保护"，以及断言写的时序深度与设计是否匹配 |
| 5 | **覆盖率缺口分析 + 自动生成 covergroup** | 手写 covergroup 枯燥且容易漏 bin；希望从 RTL 结构反推应该覆盖什么 |
| 6 | **验证缺口报告**（高风险但无 SVA / 无覆盖的信号） | 验证资源有限时，需要一个"先验哪里"的优先级列表 |
| 7 | **改动风险分级**（按信号在时钟/复位/数据路径上的位置打分） | 改一行 RTL 时，想快速知道"这次改动会牵连多大范围、风险多高" |
| 8 | **约束与随机化可达性**（rand 变量、inline constraint、randomize 调用图，找永远随机不到的分支） | 约束写死会制造"仿真永远走不到"的角落，靠覆盖率掉了才发现太晚 |
| 9 | **跨时钟域检查**（CDC） | 漏两级同步器是经典隐患；静态扫描能在设计早期发现 |
| 10 | **时序关键路径的静态推断** | 没有综合/时序报告时，想从结构上估"哪条组合链最长" |

---

**为什么一起砍掉**：这些想法都停在"能跑通 demo"的程度——没有真实项目验证、
没有锁定的判定语义、也没有说清楚失效场景。留在 CLI 里会让使用者误以为可用
（而输出可能是错的），这比没有这个命令更糟。先把想法留下，将来按 `KNOWN_LIMITATIONS`
的晋升门槛重新做。
