# P165.2 packaging rename: `trace` → `sv_query.trace`

**日期**: 2026-11-13
**状态**: ✅ 完成
**分支**: `packaging/p165-2` (从 `9c7603c5`)

## 1. 问题

顶层 `trace` 包与 Python 标准库 `trace` 冲突。旧方案依赖：

```text
sys.path.insert(.../src)
namespace package src
pyproject include trace*
```

`pip install` 后导入/console script 不稳定，且 `import trace` 可能拿到标准库。

## 2. 迁移

```text
src/trace/  →  src/sv_query/trace/
```

同步：

- 85 个 Python 模块；
- 约 600 处 `from trace...` / `import trace...`；
- `pyproject.toml` packages include / package-data；
- `cli` 内部残留的 `from src.cli...` 改为 `from cli...`，使安装后的
  `sv_query` console script 能真正运行；
- tests/tools 中硬编码的 `src/trace` 路径与动态 import 路径；
- active docs 的源码路径（历史 docs/archive/task_tree 保持原样）。

关键结果：

```text
不再安装 top-level `trace` 包
import trace  → Python 标准库
import sv_query.trace → 查询引擎
```

## 3. 辅助工具

- `git mv` + 正则批量 import 重写；
- `rg` 统计剩余引用；
- `tools/check_crap.py` 增加 **rename-aware baseline**：
  git rename 时用旧路径取 HEAD 内容、按新路径分析 namespace，
  避免 move 被误判成“全树新增函数”；
- `pip install --no-deps --target` 实际构建 wheel；
- Verilator/现有测试 gate 保证语义不变。

## 5. 迁移规则

旧：

```python
from trace.unified_tracer import UnifiedTracer
from trace.core.graph.models import EdgeKind
```

新：

```python
from sv_query.trace.unified_tracer import UnifiedTracer
from sv_query.trace.core.graph.models import EdgeKind
```

`cli` 包保持 top-level；查询引擎是 `sv_query.trace`。

## 6. 边界

- `src` 包仍保留用于 legacy `src.cli...` 路径/开发环境；不再安装 top-level trace；
- 历史 docs/task_tree 中的旧路径是时间快照，不批量改写；
- 若外部用户直接 `import trace`，现在得到标准库，不是 sv_query；这是预期。
