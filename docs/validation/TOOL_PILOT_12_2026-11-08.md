# 受限 svq_query 12 题 pilot（P98）

**日期**: 2026-11-08
**范围**: 12 题 ×2 模型 ×2 次运行 = **48 cells**
**性质**: 受限工具接口验证，不是通用 debug benchmark
**数据**: [tool_pilot_12_2026-11-08.json](tool_pilot_12_2026-11-08.json)

---

## 1. 接口

agent 只有：

```text
svq_query(intent, snapshot, signal, dst, depth)
```

并且 runner patch 禁用了：

```text
bash / read / grep / skill
```

没有 source/filelist；只允许预构建 snapshot。

---

## 2. 结果

| 模型 | exact | mean wall |
|---|---:|---:|
| MiniMax-M3 | **24/24** | **9.0s** |
| DeepSeek-Flash | **24/24** | **4.7s** |

合计：

```text
48/48 exact
```

对比原版 12-task T2（2 seed）：

| 模型 | 原版 T2 | 受限工具 |
|---|---:|---:|
| MiniMax-M3 | 63.5s | **9.0s** |
| DeepSeek-Flash | 33.5s | **4.7s** |

准确率都保持 100%；工具接口把 wall 降到约 **1/4–1/7**。

---

## 3. 工具调用

每个 cell 只有一次 `svq_query`：

```text
neighbors / fanin / fanout / path
```

没有再出现：

- bash 搜索；
- 读 source；
- 读 snapshot JSON；
- 读 `.cache`；
- 反复试探 CLI。

## 4. 为什么有效

不是 prompt 变好，而是：

```text
可用动作只有 1 个
→ 模型没有探索空间
→ 一次调用返回结构化答案
```

这验证了之前的判断：

> 瓶颈是 agent 工具接口，不是查询能力。

## 5. 对比边界

- 原版 T2 有 source + 自由 CLI；受限工具没有 source；
- 这是**接口差异**，不是纯模型能力差异；
- 只测 fanin/fanout/neighbors/path；
- snapshot 外部预构建；
- 不支持 `connections/instances`（无 MIG）；
- 12 题是手工结构任务，不是真实 debug；
- 2 次运行不是完整 2 seed 统计；
- 不作模型排名。

## 6. 结论

```text
受限工具路线成立：
- 准确性不降；
- 延迟显著下降；
- 协议由 harness 保证；
- 不再依赖 prompt/skill 说服。
```

这是目前最强的 agent 接口结果。

## 7. 下一步

1. 把 `svq_query` 插件作为可选默认接口；
2. 补 3–5 个真实/更复杂结构任务，确认不是 12 题特化；
3. 保持 CLI 作为底层，不让 agent 直接拼；
4. 不再做 prompt/skill 变体。
