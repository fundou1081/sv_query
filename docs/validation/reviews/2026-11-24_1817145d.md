## 2. Findings

### P2-1 — `from_dict` silently coerces corrupt scalar types (strictness contract gap)
**File:line**: `src/sv_query/trace/core/expression_ir.py:144` (`signed=bool(data.get("signed", False))`), `:143` (`width=data.get("width")`), `:146-147,149` (`signal`/`literal`/`reason=data.get(..., "")`), `:35` (width accepts `bool` because `bool` is an `int` subclass).

**Contract**: doc §4 "from_dict() is strict ... it does not guess"; §3 "literal is text, not int".

**Repro** (read-only probe, `/tmp/p1981_probe.py`):
```
Expr.from_dict({..., "signed": "false"}).signed       -> True     (ACCEPT, wrong)
Expr.from_dict({..., "signed": 0}).signed             -> False    (ACCEPT, wrong)
Expr.from_dict({"op":"SignalRef","signal":123}).signal -> 123      (ACCEPT, wrong type)
Expr.from_dict({"op":"Literal","literal":5}).literal   -> 5        (ACCEPT, int, not text)
Expr.from_dict({"op":"Unknown","reason":7}).reason     -> 7        (ACCEPT)
Expr.from_dict({..., "width": True}).width             -> True     (ACCEPT, bool-as-width)
```
All accepted and re-serialized. `_validate_op` (`:35`) cannot catch these because `bool()` has already normalized `signed`, and `signal`/`literal`/`reason` only get truthiness checks in `_validate_*` (`:51-63`), not type checks.

**Why P2 not P1**: not reachable in P198.1 — nothing persists/reads IR bytes yet; only malformed/untrusted `from_dict` input triggers it. It becomes a real silent-wrong-data risk only when P198.3 reads IR from cache/snapshot.

**Fix**: in `Expr.from_dict`, before constructing, assert `type(signed) is bool`; `width is None or (type(width) is int)`; `signal`/`literal`/`reason` are `str`. Mirror for `assign_type` (already validated) and `condition`. Add `__post_init__` type checks for `signal`/`literal`/`reason` so direct construction is strict too.

**Test gap**: no test feeds malformed scalar types. Add parametrized tests asserting `ValueError` for `signed="false"`, `signal=123`, `literal=5`, `width=True`, `reason=7`.

### P2-2 — Serialized form duplicates shared subtrees; doc DAG claim not met; final wire format undecided
**File:line**: `src/sv_query/trace/core/expression_ir.py:108` (`"children": [c.to_dict() for c in self.children]`) and `:230-232` (`ExpressionStore.to_dict` emits each node with its full subtree). Doc claim: `docs/dev/EXPRESSION_IR.md:86-87` "Identical subtrees share one id (DAG), so repeated operands do not duplicate serialized data."

**Repro** (`/tmp/p1981_dag.py`): diamond DAG with shared signal `x` and shared literal `4'd2` → store has 5 unique nodes (correct), but serialized JSON contains `4'd2` **5 times** and each node embeds full children. `to_dict()` therefore duplicates shared data, contradicting the doc claim. Round-trip still works and is stable.

**Forward-compat implication (user point 5)**: there is no `expr_id` child-reference and no assignment→expr root reference in the wire format; `AssignmentExpr` embeds whole trees and `ExpressionStore` re-embeds the same trees independently. Phase 2/3 will want `expr_id` references. Also, `fingerprint()` (`:153-154`) hashes the entire `to_dict()` including all default fields, so adding any field to `Expr` in phase 2 changes every fingerprint/`expr_id`. Because IR is not persisted until P198.3, this is still cheap to fix now.

**Fix**: settle the final wire format before P198.3 — either (a) serialize children and assignment sides as `expr_id` references into a flat `expressions` table (true DAG, one copy), or (b) amend the doc to state that P198.1 serialization is inline/tree and DAG compaction is deferred. If fingerprint stability across schema additions is required, hash a frozen subset / omit default-valued fields. Bump `IR_VERSION` when the format is finalized.

**Test gap**: no test asserts one-copy-in-serialization or that repeated operands share an id in the serialized bytes; the only structural assertion is `len(store) == 5` (in-memory), which passes despite duplication.
