## Findings

### P1-1 — Fix silently no-ops in `--filelist` mode (primary repro still broken)

`driver_extractor.py:1379` does `Path(loc[0]).read_text(errors="ignore")`. In filelist mode `adapter.get_source_location()` returns a **bare basename** (`picorv32.v`, `serv_csr.v`), which does not resolve from the project cwd; `OSError` is caught at line 1385–1386 and only debug-logged, so `line` stays at the condition line. This violates iron rules 2/3 (no silent fallback).

Repro (current HEAD, `--filelist`, fresh `--no-cache`):

```
python3 run_cli.py drivers picorv32_axi.picorv32_core.trap \
  --filelist /tmp/p194510_picorv32.f --json --evidence --no-cache
# driver[1] evidence: file="picorv32.v", line=1188
#   source[1188] = 'if (cpu_state == cpu_state_trap)   dbg_ascii_state = "trap";'
# parent 5c5461b9: identical line=1188  -> fix has no effect
```

Same on SERV (`--filelist /tmp/serv.f`): `serv_rf_top.cpu.gen_csr.csr.mcause31` → line 155 (condition), `mcause3_0[0]` → line 149 (condition); byte-identical to parent. Programmatic check: in filelist mode **0 / 2,475** picorv32 and **0 / 427** SERV conditional edges have a `loc.file` resolvable from cwd, so the new scanner never runs.

**Fix**: resolve the source through the compiler's `sources` map / filelist base directory (as `cli/core/semantic/trace_evidence._read_source_text()` already does) instead of raw `Path(loc[0])`; emit an explicit structured diagnostic when resolution fails instead of silently keeping the condition line. **Test gap**: new test uses `-f` only; add a `--filelist` case with a basename file path.

### P1-2 — File-wide "last assignment" rebinds conditional edges to wrong branches

`driver_extractor.py:1381-1383` calls `find_functional_assignment(leaf, text, 1, len(text.splitlines()))`, i.e. scans the **whole file** and `find_functional_assignment` returns the **last** non-reset LHS (`source_assignment.py:190-194`). It ignores elaboration (generate branches, preprocessor branches), bit-range identity and branch/condition correspondence.

Diff of conditional-edge `source_location.line` (parent → current, single-file sources mode):

- picorv32: **2,295 of 2,475** conditional edges changed; all 2,295 point at a valid LHS with the same leaf, but the statement is frequently wrong:
  - `ack_arvalid` condition `mem_axi_arready && mem_axi_arvalid`: 2798 `ack_arvalid <= 1;` → **2803 `ack_arvalid <= 0;`** (the clear branch). Same for `ack_awvalid` (2796 → 2802 `<=0`) and `ack_wvalid` (2800 → 2804 `<=0`).
  - `cpu_state`: ~20 distinct conditions (fetch/exec/shift/debug …, including text-only lines such as 1193 `dbg_ascii_state = "shift"`) → **all** collapse to **1946 `cpu_state <= cpu_state_trap;`**.
  - `cpuregs` condition `REGS_INIT_ZERO`: 1339 → **1342 `cpuregs[latched_rd] <= cpuregs_wrdata ^ 1;`**, inside inactive `` `elsif PICORV32_TESTBUG_002 `` branch (active assignment is 1344).
  - `count_cycle`: 1564 `count_instr <= count_instr + 1;` → **1436 `count_cycle <= 'bx;`** (ENABLE_COUNTERS=false branch).
- SERV (`/tmp/serv.f`): **~280 / 427** conditional edges changed;
  - `serv_rf_top.cpu.bufreg.data[1:0]`: 67 (`W==1` generate branch assignment) → **84** (`data <= …` in the mutually exclusive `W==4` branch, `serv_bufreg.v:71-87`).
  - `serv_rf_top.cpu.ctrl.o_ibus_adr`, condition `!(RESET_STRATEGY == NONE) && i_pc_en | i_rst`: 112 → **109** (the `RESET_STRATEGY == "NONE"` branch, `serv_ctrl.v:107-113`).
  - `serv_rf_top.cpu.decode.funct3` etc. (`i_wb_en`, active `gen_pre_register`, default `PRE_REGISTER=1`): 244 → **305** (`gen_post_register`, inactive, `serv_decode.v:302-313`).

Consequence: an edge's `condition` and its `evidence` now routinely describe different statements — e.g. "condition `mem_axi_arready && mem_axi_arvalid`" paired with `ack_arvalid <= 0;`. This is a silent wrong answer in an evidence surface used for verification claims, and it does **not** align with `trace evidence` either (SERV `bufreg.data[1:0]` → 66, `decode.funct3` → 244 there, vs drivers 84 / 243–305 depending on input mode).

**Fix**: scope the assignment search to the edge's enclosing always/continuous-assign block and elaborated module/generate instance (semantic AST assignment node), or at minimum use `find_assignment_near(leaf, text, hint=condition_line, window≈16)` instead of whole-file last; skip preprocessor-inactive regions. **Test gap**: the only new test has a single conditional assignment per signal, so it cannot detect this.
