## 2. 逐项核验

### 2.1 IR mapper 正确性（output bit → source bit；source bit → output bit）

- **常量左移/逻辑右移（PASS）**：实测 `y=a<<4'd2`（a[7:0], y[10:0]）fanin `y[2]..y[9] → a[0]..a[7]`，`y[0]/y[1] → []`（零填充）；fanout `a[i] → y[i+2]`。`_res_shift` 的 `delta=out_bit-amount`（左移）/`out_bit+amount`（右移）与 `_in_shift` 的 `delta=amount/-amount` 互为逆，方向正确。
- **逻辑右移 unsigned（PASS）**：`y=a>>4'd2` → `y[0]=a[2] … y[5]=a[7]`，高位 `[]`，方向正确。
- **常量移位量解析（PASS）**：pyslang 把 `4'd2` 规范成 Literal `4'b10`；`_shift_amount` 能解析 `_base_name`/radix/`int(digits, base)`，测试已间接证明。
- **动态移位（PASS，显式 unknown）**：`y=a<<b` → mapper `None`，fanin/fanout 全 `None`，无 coerce-to-zero。
- **嵌套 Concat / Slice 在 shift 下（PASS）**：`y={a,b}<<4'd2` 的 a（高 nibble）映射到 `y[6..9]`；`y=a[7:4]<<4'd2` 映射到 `y[6]=a[4] … y[9]=a[7]`。`flatten` offset 与 `min(bit_range)+out_bit` 正确。
- **Cast / 符号扩展（部分 PASS，见 F4）**：纯 Cast 根表达式（如 `assign y=a;` signed）因 `_edge_expression_ir` 只放行 shift 根而走 legacy，fanin/fanout 正确；Cast 位于 shift 子节点时符号位映射正确但高位填充不完整。

### 2.2 fanin/fanout 是否真正消费 expr_id；IR 存在时是否仍有静默 regex 回退

- **正向（PASS）**：新增 2 个测试在 `edge.expression="not-a-shift"`、`edge.source=None` 后仍得到 IR 映射；用 monkeypatch 把 `_edge_expression_ir` 置为 `None` 模拟 revert，两测试均按预期失败 → **revert-sensitive**。
- **反向（FAIL，F2）**：IR 存在但 mapper 返回 `None`（如 `Call`/`Unknown` 子节点）时，调用方把 `None` 解释为「回退 legacy」，而 legacy 仍有 `src_info.op/shift_amount` 逐位 regex/branch 逻辑，产出**伪造的精确位映射**。这直接违反本 commit 声称的「no silent regex fallback for shift when IR exists」以及契约 §P198.5「unknown/call => unknown」。

### 2.3 Signed extension via Cast；常量表达式仍正确

- 常量/纯 Cast 根仍走 legacy（signed 直连、常量边），实测正确；P197.4 的 `a<<4'dx`/`a>>4'dz`/`a<<b` 未知用例全过。无 coerce。
- 但「signed extension handled through Cast」只在 shift 内含 Cast 时经 IR 验证，且算术填充不完整（F4）；新增测试用的是 unsigned `logic`，未覆盖 signed 场景。
