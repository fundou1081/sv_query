## 逐项核验

### 1. Typed IR flatten 的 MSB/LSB 偏移与嵌套顺序 — **PASS**

`concat_layout.py:44-70` 的 `walk` 对 `{a, b, c}`（pyslang 语义操作数 MSB-first）从 `base + total_width` 起逐个减宽，得到 LSB 偏移；最后按 `offset` 排序返回 LSB-first 段。

- 静态验证：`{y2,{y1,y0}}`（各 1 bit）→ 段 `y0@0, y1@1, y2@2`。
- 实测验证（含混合宽度嵌套）：`assign {y2, {y1, y0}} = {a[3], {b[1:0], c[0]}};` 得到
  `c[0]→y0`, `b[1:0]→y1`, `a[3]→y2`（且 `_expand_slice_bit_nodes` 进一步生成 `b[0]→y1[0]`, `b[1]→y1[1]`）。顺序与 SV 拼接语义一致。
- `test_layout_pairs_nested_concat_by_lsb_offset` 断言 `flatten(lhs) == [y0,y1,y2]`、`pair == [(y0,c),(y1,b),(y2,a)]`，与实现一致。

小偏差（非阻塞）：契约 §7 的 `Segment` 定义为 `Segment(lvalue, expr, width, offset)`，实现缺少 `lvalue` 字段；P198.4 当前用途不需要它，但 P198.5 消费映射时需注意。

### 2. 按绝对位范围配对、非 leaf zip、仅等宽 — **PARTIAL / CAVEAT**

- 正向：`pair()` (`:73-95`) 先校验两侧总宽相等，再按 `[lo,hi]` 完全相等匹配，确实不是 leaf `zip`。
- 但契约 §7 原文是「Pair segments by **overlapping** absolute bit ranges」。实现用**完全相等**代替「overlapping」，因此等宽但分段边界不同的合法 case 无法配对（见 F3）。
- 更关键：`zip(lhs_elements, rhs_signals)` 的 legacy leaf-zip **仍然保留**并在配对失败时生效（`assign_extractor.py:166-232`），即 P198.4 的核心替换要求未完全落地（见 F1）。

### 3. Graph 边（`{y2,y1,y0}={a,b,c}`、嵌套、slice、无 aggregate 目标、正确 src/dst） — **PARTIAL**

成功路径实测均正确：

| RTL | 边 |
|---|---|
| `assign {y2,y1,y0} = {a,b,c};`（全 1-bit） | `a→y2`, `b→y1`, `c→y0` |
| `assign {y2,{y1,y0}} = {a,{b,c}};` | `a→y2`, `b→y1`, `c→y0` |
| `assign {y1,y0} = {a[1:0],b[1:0]};` | `a[1:0]→y1`, `b[1:0]→y0` |
| `assign {y1[1:0],y0[1:0]} = {a[3:2],b[1:0]};` | `a[3:2]→y1[1:0]`, `b[1:0]→y0[1:0]` |

- 成功路径未创建任何 `top.{...}` aggregate 节点/目标（`signal_part` 只返回 SignalRef/Slice 名）。
- **但**回退路径仍创建 aggregate 目标：`assign {y2,y1} = {a,b,c};` → `a→top.{y2,y1}`, `b→top.{y2,y1}`, `c→top.{y2,y1}`。因此「no aggregate `{...}` target」不是全局性质，只在 typed 配对成功时成立；而该 case 的测试只覆盖了成功路径。见 F1。

### 4. 宽度不匹配 / unresolved layout：显式 unknown 还是 legacy zip / 假边？ — **FAIL（F1, P1）**

实测复现：

```systemverilog
module top(input logic a,b,c, output logic y1,y0);
  assign {y1,y0} = {a,b,c};   // lhs 2 bit, rhs 3 bit
endmodule
```

`pair()` 因总宽不等返回 `None`（`concat_layout.py:79-84`），`_handle_concat_assign` 落回 legacy leaf-zip（`assign_extractor.py:166-232`），产出：

```
top.a -> top.{y1, y0}   confidence=high  expr='{a,b,c}'
top.b -> top.{y1, y0}   confidence=high
top.c -> top.{y1, y0}   confidence=high
```

问题：

- 契约 §7:144-145 要求「Width mismatch => explicit `unknown` with reason」，此处既无 unknown reason，也无 sentinel/结构化错误，且边 `confidence="high"`、`extra={}`、`expr_id=''` —— 会把不确定的拼接映射伪装成已验证驱动。
- 契约 §9 P198.4 要求「Replace `_handle_concat_assign` leaf `zip`」；代码注释 `assign_extractor.py:126-128` 自认「legacy path ... explicitly tracked as debt until P198.7」，但契约并未给出该宽限。
- `AGENTS.md` 铁律 2「禁 silent fallback；失败必须显式」被违反。

**是否可接受：不可接受。** 宽度不匹配在 SV 中合法（truncation/zero-extension），契约也只在「defined truncate/zero-extend rule」存在时才豁免，而本提交没有定义该规则。应改为：配对失败时产出显式 unknown（例如带 `unknown_reason` 的 sentinel/结构化标记或 `confidence="unknown"` 的边），且不创建 aggregate `{...}` 节点/边；不得回退 leaf zip。

### 5. 单 bit vs 范围后缀；bit_select 基线 — **PASS（成功路径）**

- `_suffix` (`assign_extractor.py:132-137`) 对 `(n,n)` 产出 `[n]`、对 `(hi,lo)` 产出 `[hi:lo]`。实测 `a[2]→top.a[2]`、`a[3:2]→top.a[3:2]`、`c→top.c`。
- 既有回归基线 `sim/tests/regression/test_bit_select_in_always.py:314-348` 断言 `{y[2],y[1],y[0]} = {a,b,c}` 产生 `a→y[2]`, `b→y[1]`, `c→y[0]`；新 typed 路径给出相同结果，3280 全量通过，**无回归**。

### 8. P0/P1/P2 明细（file:line / repro / fix / test gap）

#### F1 — P1：宽度不匹配/unresolved 回退 legacy leaf-zip（假边 + aggregate 目标）
- **位置**: `src/sv_query/trace/core/concat_layout.py:79-84`；`src/sv_query/trace/core/extractors/assign_extractor.py:126-128, 139-165, 166-232`
- **契约**: `docs/dev/EXPRESSION_IR.md:144-145`（§7）、`:197`（§9 P198.4）；`AGENTS.md` 铁律 2
- **Repro**: `assign {y1,y0} = {a,b,c};`（rhs 3 bit / lhs 2 bit）→ `a/b/c → top.{y1,y0}`，`confidence=high`，无 unknown 标记
- **Fix**: 配对失败时发出显式 unknown（结构化标记/sentinel 或带 `unknown_reason` 的低置信度边），禁止生成 aggregate `{...}` 节点，删除/禁用 legacy leaf-zip 回退
- **Test gap**: 需新增 graph 级测试断言 mismatch 时无 `top.{` 目标且存在显式 unknown

#### F2 — P1：动态 select 段静默降级为整信号驱动
- **位置**: `src/sv_query/trace/core/concat_layout.py:98-106`（`signal_part` 未检查 `expr.bit_range is None` 或 `expr.reason`）；`assign_extractor.py:142-145`
- **契约**: `docs/dev/EXPRESSION_IR.md:146`（§7 "Dynamic selects => `unknown` for that segment"）
- **Repro**: `assign {y1,y0} = {a[c], b[0]};`；`a[c]` 的 IR 为 `Slice(bit_range=None, reason='dynamic or unresolved select')`，实测边为 `top.a -> top.y1`（整 4-bit 总线驱动 1 bit），而应为该段 unknown
- **Fix**: `signal_part` 对 `bit_range is None` 或 `reason` 非空返回 `None`；调用处对 `None` 发显式 unknown 而不是 `continue` 静默跳过
- **Test gap**: 需新增 dynamic-select graph 测试；注意 `assign_extractor.py:144-145` 的 `continue` 是 silent skip

#### F3 — P2：等宽但不同分段无法配对（overlapping 要求未满足）
- **位置**: `concat_layout.py:86-94`（要求 `l_lo==r_lo and l_hi==r_hi`）
- **契约**: `docs/dev/EXPRESSION_IR.md:143`（"Pair segments by overlapping absolute bit ranges"）
- **Repro**: `assign {y1,y0} = {a[1:0]};`（两侧各 2 bit）→ `pair()` 返回 `None` → legacy 只产 `a[1:0]→y1`，`y0` 无驱动；反向 `{a[1:0]} = {y1,y0}` 同样丢 `y0`/`y1` 一位
- **Fix**: 实现重叠位范围切分（宽段按 overlap 拆给多个窄段，或反之合并），至少对无法切分的情况显式 unknown 而非 legacy
- **Test gap**: 需新增 mixed-segmentation 等宽测试

#### F4 — P2：字面量段被静默丢弃
- **位置**: `assign_extractor.py:144-145`（`if lhs_part is None or rhs_part is None: continue`）；`concat_layout.py:98-106`（`signal_part` 仅识别 SignalRef/Slice）
- **契约**: `docs/dev/EXPRESSION_IR.md:142`（concat 段可为 literal）；`AGENTS.md` 铁律 2
- **Repro**: `assign {y1,y0} = {a[0], 1'b0};` → 仅 `a[0]→y1`，`y0` 无驱动、无 constant/unknown 标记
- **Fix**: 对 literal 段产出显式常量驱动或显式 unknown 标记，不留无声空洞
- **Test gap**: 需新增 literal 段测试

#### F5 — P2：新边未挂接 IR（`expr_id`/`assignment_id` 为空）
- **位置**: `assign_extractor.py:158-160`（`append_edge` 未传 `expr_id`）；`graph_builder.py:212-214`（`_assignment_ir` 对 `"{" in lhs_name` 直接 return None）
- **契约**: `docs/dev/EXPRESSION_IR.md:120-124`（§6 "Annotate driver edges with expr_id"）
- **Repro**: 所有新 concat 边实测 `expr_id=''`、`assignment_id=''`；图 `assignments` 数为 0
- **评价**: 此为空 IR 挂接在 P198.3 已存在，但 P198.4 新增的边延续了该缺口，P198.5 的 `map_bit` 路由无法消费这些边。属 IR 方向一致性问题，非本次功能正确性核心
- **Fix**: 让 P198.4 生成的逐段边记录对应 `AssignmentExpr`/`expr_id`（即使 LHS 是 aggregate，也应按段记录）
- **Test gap**: 需断言新边带 `expr_id`

#### F6 — P2：`flatten` 对未知宽度 Slice 的错误回退
- **位置**: `concat_layout.py:27-32`（`if expr.op == "Slice": return expr.children[0].width`）
- **契约**: `docs/dev/EXPRESSION_IR.md:115`（`width is None` 必须当 unknown）、`:146`
- **Repro**: 人工构造 `Expr(op="Slice", width=None, children=(SignalRef(width=4),))` 时，`_segment_width` 返回 4 而非 unknown，offset 计算被污染。当前 pyslang builder (`expression_builder.py:121-142`) 总给出 width，故未观测到实际错误
- **Fix**: Slice 且 `width is None` 时返回 `None`，让 `flatten` 整体判 unknown
- **Test gap**: 需单元测 `Slice(width=None)` → `flatten() is None`

#### F7 — Caveat：圈复杂度
- `_handle_concat_assign` CC 38→49（`tools/run_gates.sh` 因存量超限未拦截）。建议后续拆分 typed 路径为独立 helper，避免继续膨胀。
