## What is correct (avoid false positives)

- The fix is narrow and semantic: keyed on pyslang node kind, signedness and width;
  no source-regex substitute, no name-prefix guessing, no fabricated bit for
  unknown width.
- `_cast_extends_sign` now keys on the **child output sign bit being present in the
  mapped value set** (`child.width - 1 in vals`) rather than on the input bit index,
  which is the correct trigger for sign extension through a nested shift.
- `_in_shift` filters out-of-expression result offsets
  (`0 <= v + delta < expr.width`), removing the fabricated `a[7] -> y[8..10]`;
  the early `return []` removed from `_in_cast` is safe because callers pass only
  valid source bits and `_expr_dst_bits` filters to `0 <= b < dst_w`. The direct-cast
  probe (`/tmp/p19719_cast_check.py`) confirms no spurious fanout appears.
- `_res_cast` returning `[]` for a literal/zero-extension branch is correct for
  dependency tracking: a constant extension bit depends on no source signal.
- No `except ...: pass`, no `--no-strict`, no silent fallback introduced; `None`
  still propagates for unmappable IR (P198.5 F2 preserved).
- Prior P197.13/17/18/P198.5/9/11 scenarios remain intact (36 targeted + 3363
  canonical passed).
- No new `CLAIMS.md` row was added — correct: this is a correctness fix to a
