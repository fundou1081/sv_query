## Verification against the requested points

### 1. `pair()` overlapping split — ascending/nested/slices: PASS; descending: FAIL (P1-1)

For ascending ranges the interval-intersection algorithm is sound: the two segment lists
are disjoint partitions of `[0,total_width)`, so emitting one `ConcatPair` per overlap
yields exactly one mapping per bit — no duplicates and no dropped bits. Verified with
probes `/tmp/p1988_probe.py`, `/tmp/p1988_probe2.py`, `/tmp/p1988_probe3.py`:

| form | result |
|---|---|
| `{y1,y0} = {a[1:0],b[1:0]}` | `a[1:0]→y1`, `b[1:0]→y0` + correct per-bit edges |
| `{y} = {a[1:0],b[1:0]}` (wide LHS, narrow RHS) | `a[1:0]→y[3:2]`, `b[1:0]→y[1:0]` |
| `{y1,y0} = {a[1:0]}` (narrow LHS, wide RHS) | `a[1]→y1`, `a[0]→y0` |
| `{y2,{y1,y0}} = {a,{b,c}}` (nested) | `a→y2`, `b→y1`, `c→y0` |
| `{y[3],y[2:0]} = {a[2:0],b}` (both sides split) | `y[2:1]←a[1:0]`, `y[3]←a[2]`, `y[0]←b` |
| `{y0,y1} = {a[3:2],b[1:0]}` (non-zero-base slices) | correct |
| `{y3,y2,y1,y0} = {a[3:0]}` | `yk←a[k]` for all four bits |

No duplicate/wrong mappings were found for ascending ranges.

**Little-endian (`[0:N]`) packed ranges are mapped in reverse** — see **F-1988-P1-1**.
Parent emitted an explicit unknown for this shape; this commit silently emits reversed
edges, so it is a regression, not a pre-existing limitation being merely exposed.

## Findings

### F-1988-P1-1 — P1: reversed bit mapping for little-endian packed ranges on overlapping split

- **Where:** `src/sv_query/trace/core/concat_layout.py:81-85` (`_subexpr` Slice branch
  computes `base = min(expr.bit_range)` and maps relative bit `k → base + k`) combined
  with the LSB-offset convention in `pair()` (`:95-115`).
- **Repro** (`/tmp/p1988_desc.py`, `/tmp/p1988_desc_ref.py`):
  ```systemverilog
  module top(input logic [0:1] a, input logic [0:1] b, output logic [0:3] y);
    assign {y[0:3]} = {a[0:1], b[0:1]};
  endmodule
  ```
  New commit graph edges: `a[0:1]→y[3:2]`, `b[0:1]→y[1:0]`, plus bit edges
  `a[0]→y[2]`, `a[1]→y[3]`, `b[0]→y[0]`, `b[1]→y[1]`.
  Equivalent explicit assignments (`assign y[0]=a[0]; …`) in the *same* tool produce
  `a[0]→y[0]`, `a[1]→y[1]`, `b[0]→y[2]`, `b[1]→y[3]`. The concat path is reversed.
  Parent `35657143` emits a single `concat_layout` unknown and no edges for this shape.
- **Impact:** silent wrong bit answer from a normal, legal SystemVerilog declaration
  style; no unknown is recorded (`unknowns == []`). Newly introduced by this commit.
- **Fix:** determine declaration direction from `expr.bit_range` (msb<lsb means
  little-endian) and map relative bit `k` to `bit_range[1]-k` with the corresponding
  reversed offset convention — or, if little-endian is out of scope, make `_subexpr`
  return `None` (explicit unknown) for such slices until properly supported.
- **Test gap:** no committed test uses `[0:N]` packed declarations; add one asserting
  either the correct mapping or an explicit unknown.

### F-1988-P2-1 — P2: 1-bit slice LHS targets miss refs; orphan assignment entries

- **Where:** `src/sv_query/trace/core/graph_builder.py:211` builds
  `suffix = f"[{rng[0]}:{rng[1]}]"` for every range, while the single authoritative
  graph naming rule in `src/sv_query/trace/core/extractors/assign_extractor.py:142-147`
  (`_suffix`) emits `[k]` when `rng[0] == rng[1]`. Two implementations of one naming
  rule also breach AGENTS.md iron rule 8.
- **Repro** (`/tmp/p1988_orphans.py`, direct `_concat_targets` call):
  ```systemverilog
  assign {y[3],y[2],y[1],y[0]} = {a[3],a[2],a[1],a[0]};
  ```
  `_concat_targets` → `['top.y[0:0]','top.y[1:1]','top.y[2:2]','top.y[3:3]']`;
  actual edge dsts are `top.y[0]` … `top.y[3]`. All 4 edges keep
  `expr_id=''`/`assignment_id=''` and assignment `assign:adbeddadf06512f5` is orphaned.
  Also reproduces on `{y[3], y[2:0]} = …` (only the `y[2:0]` edge gets a ref) and
  on `{y} = {a[1:0],b[1:0]}` with a 4-bit `y` when a 1-bit split occurs.
- **Impact:** the headline requirement "concat edges get refs / assignment table no
  orphans" is not met for a common concat form. No wrong answer and no false-verified
  state, so P2 per the precedent in
  `docs/validation/reviews/2026-11-24_a163963.md:112-124`, but it must be fixed or
  explicitly scoped before the item is closed.
- **Fix:** share one suffix helper (or emit `[k]` when `rng[0]==rng[1]`), then assert
  refs on every continuous concat edge and `referenced == set(graph.assignments)`.
- **Test gap:** committed `test_graph_concat_edges_carry_ir_refs` uses only whole-signal
  LHS (`y1`, `y0`), which never exercises the single-bit-slice naming path.
