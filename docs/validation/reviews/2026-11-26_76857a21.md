## Verification results

### 1. Signed `>>>` fills with sign bit; `>>` and unsigned `>>>` zero-fill — PASS

Probe (`/tmp/p19717_probe.py`, `/tmp/p19717_inverse.py`, `/tmp/p19717_repro.py`):
`input logic signed [7:0] a; output logic signed [10:0] y;`

| expression | y[5] | y[6] | y[9] | y[10] |
|---|---|---|---|---|
| `a >>> 4'd2` | a[7] | a[7] | a[7] | a[7] |
| `a >> 4'd2` | a[7] | a[7] | `[]` | `[]` |
| `a >>> 4'd2` (unsigned a) | a[7] | unmapped | `[]` | `[]` |

The IR is `ShiftRightArithmetic` for `>>>`, `ShiftRight` for `>>` (`expression_builder.py:14-16`).
`_res_shift` (`bit_mapping.py:86-96`) maps an out-of-range result bit to `child.width-1`
only for `ShiftRightArithmetic` with a signed child. `>>` and unsigned `>>>` do **not**
sign-fill; their actually vacated top bits (9, 10) are `[]` (known zero dependency).

Note (not a defect): for signed `a`, bits 6–8 of `a >> 2` are a[7]. pyslang propagates the
11-bit assignment context into the left operand, so `a` is first sign-extended to 11 bits;
bits 6–8 are operand bits, not shift-vacated bits. This matches IEEE 1800 §11.4.10/§11.6.
The new test correctly checks bit 9, the vacated bit.

Prior F2 repro now passes: `y[9:0] = a >>> 2` and `$signed(a) >>> 2` both give
`y[7]=y[8]=y[9]=a[7]` (on parent these were `[]`).

### 2. Sign-bit fanout covers fill range; inverse consistency — PASS for scope

`_shift_sign_fill` (`bit_mapping.py:173-180`) starts fill at
`max(0, child.width - amount)`. For `a >>> 2`, `a[7] -> y[5..10]` (normal bit 7−2=5
plus fill 6..10); result direction maps `y[5..10] -> a[7]`. Exact set equality in both
directions was checked for `>>>`, `>>`, unsigned `>>>`, `<<<`, `<<`, `$signed(a >>> ...)`,
`$signed(a <<< ...)`, `$signed(a >> ...)`, `$signed(a) >>> ...`, amounts 0/1/2/9/12 and result
widths 6/8/10/11. `INVERSE OK` for every in-scope case. Equal-width (`y[7:0] = a >>> 1`,
closing the prior F2 test gap) also passes.

### 3. `<<<` zero-fill, no fabricated bits, dynamic shift stays `None` — PASS

- `<<<` and `<<` low bits are `[]` for all amounts 0/1/2/7/8/12 and widths 6/8/11

- `<<<` maps to `ShiftLeftArithmetic`, `<<` to `ShiftLeft`; `_in_shift` treats both as
