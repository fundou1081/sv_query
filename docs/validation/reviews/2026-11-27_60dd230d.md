### R-P1 (BLOCKING, new) — nested `<` / `>` comparisons still report `complete`

**File:** `src/sv_query/trace/core/graph/analyzer/controlflow_analyzer.py:219-236` (`_looks_like_inline_condition`); regex at line 233.

Repro (pure inline):
```systemverilog
module top(input logic a, input logic [3:0] s, output logic y);
  localparam logic [3:0] IDLE = 4'd0;
  assign y = a & (s > IDLE);   // also a & (s < IDLE), a + (s > IDLE)
endmodule
```
- Observed on 60dd230d: `condition_status="complete"`, `warnings=[]`.
- Expected per C-62 / `docs/USER_GUIDE_EN.md:225-230`: `not_modeled` + "inline expression condition not modeled" warning.

Mixed form:
```systemverilog
always_comb begin if (en) q = a; else q = ~a; end
assign q = a & (s > IDLE);
```
- Observed: `condition_status="complete"` with only the `[Mutex] if/else` warning — the required "mixed controlflow" warning is absent; expected `partial`.

Measured matrix on HEAD (all via `run_cli.py controlflow analyze ... --json`):
| expression | status |
|---|---|
| `a & (s == IDLE)`, `a \| (s == IDLE)`, `a ^ (s == IDLE)`, `a + (s == IDLE)` | `not_modeled` ✅ |
| `a & (s <= IDLE)`, `a + (s >= IDLE)`, `a + (s != IDLE)` | `not_modeled` ✅ |
| `a & (s > IDLE)`, `a & (s < IDLE)`, `a + (s > IDLE)` | **`complete`, no warning** ❌ |
| flat `s > IDLE` / `s < IDLE` | `not_modeled` ✅ (semantic root op) |

Root cause (two coupled gaps):
1. `source.inner_ops` is populated by `driver_extractor._detect_inner_ops` with **symbolic** strings (`["==", ">", "&", "+", ...]`), but the new check `any(str(item) in cls._INLINE_OPS ...)` compares against **enum names** (`"Equality"`, `"GreaterThan"`, ...). The branch is dead for real metadata — proved by an in-process edge probe (`state_q -> top.q`, `op="BinaryAnd"`, `inner_ops=["=="]`), and by a direct helper probe (`inner_ops=["Equality"]` → `True`; real `inner_ops=["=="]` → `False`).
2. The retained regex `(==|!=|<=|>=|&&|\|\||\?|\bcase\b)` has no bare `<` / `>`. So a nested `>` / `<` is detected by neither path.

Note on provenance: this shape also returns `complete` at parent `bca8e0d1` (the old regex had the same omission), so it is not a regression *introduced* by `4c8d3533`; it is a sibling gap the rework did not close. The prior audit's fix request ("consult semantic `source.inner_ops` … and/or retain the expression fallback for all ops") is only partly satisfied.

**Fix required (narrow):** make inline classification recognize the symbol representation actually stored in `inner_ops` (e.g. map `==`, `!=`, `<`, `>`, `<=`, `>=`, `&&`, `||`, `?` alongside the enum names), or otherwise ensure nested `<`/`>` is caught without false-positiving on `<<`/`>>`. Add `<` and `>` cases to `test_nested_inline_comparison_is_not_complete` for both pure and mixed forms. Re-audit required.

**Test gap:** the new regression test covers only `==`; it passes while R-P1 is live. Prior P2-1 (revert-sensitivity breadth) is therefore only partially closed.
