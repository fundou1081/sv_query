## 1. Verdict + release safety

**Verdict: PASS WITH P1 FINDINGS — 0 × P0, 3 × P1, 7 × P2.**

0.3.9 is *operationally* healthy (no crash, no data loss, no silent cache fallback, deterministic
snapshots, honest conservative `verified=false` where checks fail). But the three P1 findings
attack the product's central promise — “objective verification” — by letting a CLOCK edge be
**verified as a data driver**, letting `trace evidence` return `is_verified=true` on a **condition
line rather than an assignment**, and emitting **36 false reciprocity violations** on picorv32
because a text regex is used where the semantic node kind is available.

All three P1s are **pre-existing**: the same code is present at tag `v0.3.8` (checked with
`git show v0.3.8^{commit}:<path>`). They are **not regressions introduced by 0.3.9**, but 0.3.9
ships them. Per AGENTS.md iron rule 14 / CODE_REVIEW_PROTOCOL (open P1 blocks release), a published
0.3.9 should be followed by a **0.3.10 fast-follow patch** plus claim/known-limitation updates;
until then the release must not be described as “agent-facing objective verification without
caveats”. No un-publish or emergency rollback is warranted (no P0, no data loss).

**No false completion found**: `PLAN.md:601` still marks `P194.5d <阻塞>` (charter-only) and
`PLAN.md:22,692` / `CURRENT_TODO.md:12` still mark `P193.10 <待做>`. `CHANGELOG.md` mentions only
the *acceptance charter*, not a completed benchmark. `README.md:140,171` explicitly says token
cost / cold-warm are not split. This matches the prior release review
(`docs/validation/reviews/2026-11-28_664dc7f2.md:109-112`).

```bash

$SVQ paths top.clk 'top.q[14:12]' -f /tmp/w039_bitclk.sv --directed --json
```

## 5. Top 5 highest-leverage architecture fixes

1. **Make `DATA_EDGE_KINDS` the only authority for every fanin consumer.** Change
   `_incoming_pairs`/`_find_drivers` to filter edge kinds, route `verify_driver` through the same
   policy, and make snapshot evidence candidate ranking data-edge-first. Closes W039-01 and
   W039-04 together; directly restores “two commands never disagree”.
2. **Redefine `is_verified` as an assignment-binding check, not a token check.** Require
   `_line_is_lhs(source_text, signal)` or semantic `assignment_id`; never promote `edge.condition`
   to verified source text; expose `verification_basis` and which driver was chosen among
   multiple drivers. Closes W039-02 and prevents score 1.0 on condition lines.
3. **Replace ID-string classification with semantic node kinds in verification.** Use
   `NodeKind.CONST` for literal exclusion in reciprocity/condition logic and add x/z true-negative
   + mutation tests. Closes W039-03 and removes a fact-layer regex heuristic.
4. **Unify the session protocol and advertise its real verification surface.** Accept the
   documented `arguments` object (or correct `SESSION_CONTRACT`), implement or explicitly declare
   per-check support for `verify_consistency`, and make CLI/session result shapes comparable.
   Closes W039-06/W039-07.
5. **Close canonical-identity and snapshot-metadata gaps.** Resolve `ports <module>` through
   elaborated instance paths / module types, and report snapshot `edge_count` as canonical-unique
   (plus raw if needed). Closes W039-08/W039-09.

**Cost**: fixes 1–3 are narrow, behavior-visible core changes requiring independent re-review per
AGENTS rule 14 and a `GRAPH_SEMANTICS_VERSION`/cache invalidation decision only if graph content
changes (these fixes change query/verification interpretation, not graph serialization, so a
claim/contract update plus tests should suffice; W039-09 would change snapshot metadata and needs a
version bump decision). Fix 4 is protocol/docs + shared verifier work. Fix 5 is discoverability
and metadata consistency.
