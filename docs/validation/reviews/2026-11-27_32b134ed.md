### P1-2 — file-wide last assignment → **PARTIALLY RESOLVED; still P1**

`find_assignment_line()` scores every same-leaf LHS line by (a) overlap of condition tokens with the preceding 6-line context, (b) +50 for RHS expression match, (c) +20 for condition tokens in the raw line, and breaks ties by distance to the condition line. This fixes the mass collapse (e.g. FAIL29's ~20 `cpu_state` conditions → 1946 trap; SERV `bufreg.data` → 84 in the `W==4` branch) and the clear-branch bug (`ack_arvalid` 2798 vs 2803).

It does **not** solve branch identity when branches share the same RHS and condition tokens:

- `picorv32_axi.picorv32_core.cpuregs[latched_rd]`, cond `resetn && cpuregs_write && latched_rd`, expr `cpuregs_wrdata` → target **1340** `cpuregs[latched_rd ^ 1] <= cpuregs_wrdata;` (inside inactive `` `ifdef PICORV32_TESTBUG_001 ``). Active assignment is **1344** `cpuregs[latched_rd] <= cpuregs_wrdata;`. All three mutually exclusive preprocessor branches (1340/1342/1344) score identically; the distance tie-break picks the closest (1340). FAIL29 picked 1342 (the `TESTBUG_002` branch) — still wrong, just a different inactive branch.
- `cpu_state`, cond `…cpu_state_ld_rs1 && 1'b1 == is_jalr_addi_slti_sltiu_xori_ori_andi` → target **1710** `cpu_state <= cpu_state_shift;` (belongs to the preceding `is_slli_srli_srai && !BARREL_SHIFTER` case item). The matching case item is at 1712 with `cpu_state <= cpu_state_exec;` at **1722**. Empty `edge.expression` removes the +50 disambiguator, so the distance tie-break wins the wrong branch.
- Bit-range identity is ignored: `leaf = signal.rsplit(".",1)[-1].split("[",1)[0]`. 84/2178 changed picorv32 edges resolve to a *different bit* of the same leaf (mostly `mem_rdata_q[14:12]`/`[31:25]` → line 442 `mem_rdata_q[31:20] <= …`; also `reg_next_pc[1:0]` → `reg_next_pc[0] <= 0;`). SERV has 0 such mismatches.

Consequence: an edge's `condition` and `evidence` can still describe different statements — the exact class of silent wrong answer C-78 is meant to eliminate. The new test only has one conditional assignment per signal with distinct RHS, so it cannot detect any of these cases.
