## Findings (residual, all P2 — non-blocking)

### P2-R1 — snapshot validation skipped when `expression_store` is missing/empty
**Files:** `src/sv_query/trace/core/graph/models.py:886` (the whole validation block
`:899-912` is nested under `if store_data:`).
**Repro:** take valid `g.to_dict()`, `d.pop("expression_store")` (or set `{}`), leave edge
`expr_id`/`assignment_id` intact; `SignalGraph.from_dict(d)` succeeds with
`assignments == {}`, empty store, yet 2 DRIVER edges still carry dangling refs.
**Fix:** hoist the edge-ref validation outside `if store_data:` so it always runs; require
both IR keys present whenever any edge carries a ref, while keeping legacy snapshots
(no refs at all) valid. This completes F2 for the reverse partial-payload direction.
**Test gap:** no test for missing/empty `expression_store` with surviving edge refs
(`test_snapshot_dangling_ir_ref_is_rejected` only mutates a complete payload).

### P2-R2 — `assign` inside generate-for with bit-select LHS not linked
**Files:** `src/sv_query/trace/core/graph_builder.py:212` (`get_signal(raw.left, None,
current_module=module)` ignores the `.genvar_ctx` / `__scope_path__` that `get_assignments`
attaches) and `:223` (target built as `f"{module_name}.{lhs_name}"`).
**Repro:**
```systemverilog
module top(input logic [7:0] a, output logic [7:0] y);
  genvar i;
  generate for (i=0;i<2;i=i+1) begin : G
    assign y[i] = a[i];
  end endgenerate
endmodule
```
Graph has DRIVER edges `top.a[0]→top.y[0]` and `top.a[1]→top.y[1]`, but both have
`expr_id=''`, `assignment_id=''`; assignment table has 1 orphan entry. Pre-existing in
5c396b25; not introduced by the rework. (Generate-for *submodule instances* are fine —
verified in item 2.)
**Fix:** pass the assign node's genvar/scope context into `get_signal`, derive the
instance/scope-qualified LHS used by the driver extractor, and emit one aid per elaborated
generate entry.
**Test gap:** no test for continuous assigns inside generate blocks with bit-select LHS.

### P2-R3 — ref validation checks existence only, not expr↔assignment correspondence
**Files:** `src/sv_query/trace/core/graph/models.py:906-912`.
**Repro:** build a design with two *different* RHS expressions (`subA: y=a<<2`,
`subB: y=a+5`), take `to_dict()`, swap the two DRIVER edges' `assignment_id` values;
`from_dict` accepts it, yet `edge.expr_id != assignments[edge.assignment_id].rhs.expr_id`
for both edges (confirmed by probe). Contract `docs/dev/EXPRESSION_IR.md` §6 requires no
stale/mismatched refs. Requires a hand-corrupted snapshot; not reachable via normal
serialization.
**Fix:** additionally assert `store.get(edge.expr_id) == assignments[edge.assignment_id].rhs`
(and LHS/target consistency where available).
**Test gap:** no mismatched-ref snapshot test.
