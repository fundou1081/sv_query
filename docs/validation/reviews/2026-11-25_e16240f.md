## 1. `_bit_index_of` metadata-first; array/slice unchanged — PASS

New code (`signal.py:1035-1047`) reads graph metadata before the id regex:

- `node.extra["array_element"]` → `None` (unpacked array element guard retained).
- `parent_bit_start` + `parent_bit_end` both present → returns the index only
  when `start == end`; a slice (`start != end`) returns `None`.
- Falls back to `re.search(r"\[(\d+)\]$", node_id)` only when metadata is absent.

In-memory probe (`/tmp/p1979_probe.py`) on constructed `SignalGraph` nodes:

| node | metadata | new `_bit_index_of` | old (regex-only) |
|---|---|---|---|
| `top.a[3]` | parent_bit_start=0, end=7 (misleading id) | **None** | 3 (wrong) |
| `top.a[5]` | start=end=5 | 5 | 5 |
| `top.b[9]` | no metadata | 9 (fallback) | 9 |
| `top.mem[1]` | `extra.array_element=True` | None | None |
| `top.c[7:4]` | start=4, end=7 | None | None |

Conclusion: metadata-first is real (the misleading-id case now returns
`None`), and array/slice behavior is unchanged. No P0/P1.

## 2. `_expand_bit_children` semantic parent/range, unresolved fallback, C-64 — PASS (with P2-2)

New code (`signal.py:298-312`) classifies a child as either
`parent == signal_id and bit_range is not None` (semantic) or
`parent is None and nid.startswith(signal_id + "[") and "]" in ...`
(unresolved-parameter fallback). In-memory probe confirmed:

- semantic child whose id does **not** carry the bus prefix
  (`top.bus_bit3`, parent=`top.bus`, bit_range=`[3:3]`) is now included — the
  old prefix scan missed it.
- prefix-looking node with a **different** parent (`top.bus[99]`, parent=
  `top.other`) is now excluded — the old prefix scan wrongly included it.
- unresolved alias (`gray_out[WIDTH-1:0]`, parent=None) is still included via
  the fallback.

C-64 depth-alias fixture (`sim/tests/unit/test_p194_5i_depth_alias.py`) passes
all three tests at target. A direct graph probe shows the fixture genuinely
contains both kinds of children:
`bin2gray.gray_out[WIDTH - 1:0]` (parent=None → fallback path) and
`bin2gray.gray_out[31:0]` / `bin2gray.bin_in[31:0]` (parent set + bit_range
→ semantic path), so both branches of the new condition are exercised.
Depth-1 suppression still works (`gray_out[31:0]` absent from depth-1 drivers).

**Caveat (P2-2):** the `bit_range is not None` conjunct excludes plain
ElementSelect bit nodes that have `parent` set but no `bit_range` — e.g. in
`sim/tests/fixtures/bus_bit_aggregation.sv` the nodes `top.bus[0]` and
`top.bus[1]` have `parent='top.bus'` but `bit_range=None` (created at
`graph_builder.py:1805-1819`, which sets `bit_range` only for RangeSelect).
Those nodes are not reached by `semantic_child` nor by `unresolved_child`.
In practice this is benign: the builder always creates a `BIT_SELECT` edge
from such a child to its parent (`graph_builder.py:1832-1838`), so aggregation
happens earlier in `_expand_incoming_bit_select` (`signal.py:144-148`) before
`_expand_bit_children` is called. The 3325-test suite shows no regression and
the C-64 case is intact. Latent edge case only, not a P1.
