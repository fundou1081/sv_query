## Findings

### F1 — P1 (NEW, introduced by this commit): slice-destination offsets use parent-LSB against a slice-relative bit → all dependencies dropped

- **file:line**: `src/sv_query/trace/core/query/signal.py:801-803`
  ```python
  elif "[" in dst_id:
      parent = self.graph.get_node(getattr(dst_node, "parent", "") or "")
      ir_bit = self._physical_to_lsb_offset(parent, want_bit)
  ```
- **Root cause**: for a part-select destination node (`top.y[2:5]`), `want_bit` is the
  **relative bit inside the slice** (confirmed by instrumenting the real call path:
  `_expand_incoming_bit_select` at `signal.py:333` passes `self._rel_bit(src, bit_filter)`;
  probe showed `want_bit=2` for `top.y[4]` and `want_bit=0` for `top.y[2]`). The new code
  feeds this relative value into a conversion keyed on the **parent bus** declaration.
  For ascending `[0:7]`, parent LSB is 7 while the slice LSB is 5, so the computed IR bit is
  `7 - r` (5, 7 for r=2, 0) instead of `3 - r`. With IR width 4 (`Cast w=4` around the shift)
  both values are out of range, so `output_source_bits` returns `[]` ("known no dependency").
- **Repro (public API, HEAD)**:
  ```systemverilog
  module top(input logic [7:0] a, output logic [0:7] y);
    assign y[2:5] = a << 2;
  endmodule
  ```
  `UnifiedTracer(...).trace_fanin("top.y[2]")` → `[]`; `top.y[3]` → `[]`; `top.y[4]` → `[]`;
  `top.y[5]` → `[]`. Independent pre-fix copy (parent `1f39223a` signal.py) gives
  `top.y[4]`/`top.y[5]` → `['top.a']` (bus fallback). HEAD therefore **removes** a real
  dependency and reports a false "no source" for a normal SV partial assignment.
- **Not shift-only**: same regression for a concat RHS on an ascending slice
  (`assign y[2:5] = {a[1:0], a[3:2]};`): parent → `['top.a[1:0]', 'top.a[3:2]']`, HEAD → `[]`
  on all four slice bits. Descendant of the new `elif` branch, not of the shift helpers.
- **Impact**: silent wrong answer / false "known nothing drives this bit" (P1 per protocol
  §4). Descending declarations are unaffected (parent LSB = 0, conversion is identity), which
  is why P198.4/P198.11 stay green — the bug is masked by the descending-only fixtures.
- **Fix direction**: first convert the slice-relative `want_bit` to its absolute physical
  index in the parent (using the slice node's `parent_bit_start` / `parent_bit_end` and
  declaration direction), then apply `_physical_to_lsb_offset(parent, ...)`. Alternatively
  map relative→IR bit using the slice's own LSB end (`slice_lsb_physical - parent_phys`).
  A guard that returns `None` (explicit unknown) when `parent` metadata is missing/zero-width
  would also prevent the silent `[]`.
- **Test gap**: no committed test drives an IR-mapped expression (`ShiftLeft`, `Concat`,
  `And`, …) into a **multi-bit part-select of an ascending bus**. The new file only exercises
  full-bus destinations (`top.y`). Add an ascending slice-destination fanin/fanout regression
  that fails on the pre-fix code and on the current code.

### F2 — P2 (residual, pre-existing, explicitly owned by P197.13): arithmetic/logical shift still collapsed; `>>>` sign-fill bits unmapped

- **file:line**: `src/sv_query/trace/core/expression_builder.py:14-15` (both
  `arithmeticshift{left,right}` and `logicalshift{left,right}` → `ShiftLeft`/`ShiftRight`);
  `src/sv_query/trace/core/bit_mapping.py:83-88,144-161` (`_res_shift` / `_in_cast` delegate
  out-of-range bits to legacy, which returns `[]` instead of the sign bit).
- **Repro (HEAD, descending buses — unchanged by this commit)**:
  `input logic signed [7:0] a, output logic signed [10:0] y; assign y = a >>> 4'd2;` →
  `y[9]`, `y[10]` return `[]`; expected `a[7]` (sign fill). Same for
  `$signed(a) >>> 2` with `y [9:0]` → `y[8]`, `y[9]` return `[]`.
- This is exactly prior review F4/C2 (`docs/validation/reviews/2026-11-24_22c4f2a.md:22,90`,
  `2026-11-24_c3e8e9f.md:71`) assigned to P197.13. The new `$signed(a) >>> 2` test
  (`test_p197_13_shift_direction.py:40-44`) only checks bits 7 and 9 (non-fill region), so it
  does not exercise or close F4. Not introduced by this commit, but P197.13's charter includes
  it, so the item cannot be marked complete while F4 stands.
- **Test gap**: no signed-vs-unsigned fill comparison, no `>>>`/`>>` fill-bit assertion, no
  "result width == source width" arithmetic shift case.

### F3 — P2 (coverage debt): committed matrix is narrower than the claim

- The new test file (53 lines) covers only **ascending source → ascending dest** and
  **ascending source → descending dest**, and only for fanin; fanout is a single `<<` case.

## What is correct (to avoid false positives)

1. **Conversion helpers are direction-correct** for ordinary buses.
   `width=(left,right)`; `_physical_to_lsb_offset` / `_lsb_offset_to_physical` use
   `right + offset` / `right - offset` per declared direction, including non-zero LSB
   (`[9:3]`, `[3:9]`) and scalars `(0,0)`. Verified against hand-computed models.
2. **Full-bus fanin/fanout matrix passes independently** for all 20 combinations
   (source `[7:0]`/`[0:7]` × dest `[9:0]`/`[0:9]` × `<< 2`, `>> 2`, `<<< 2`, `>>> 2`,
   `$signed(a) >>> 2`). `<<`/`<<<` and `>>`/`>>>` map identically as expected for unsigned;
   `$signed` Cast is unwrapped correctly by `_edge_expression_ir` (`signal.py:768-775`).
   Zero-fill bits return `[]`, never a fabricated source bit.
3. **Fanin/fanout inverse consistency verified** for all 20 combinations: for every
   fanout `a[p] → y[q]`, `output_source_bits` includes `a[p]` at `q`, and vice versa, modulo
   the documented legacy-delegated extension bits. No asymmetric/fabricated bit found.
4. **Extension-bit `None` is pre-existing and safe**: for `>>` / `>>>`, the two top result
   offsets return `None` from `_expr_source_bits` (Cast delegates zero/sign extension to
   legacy). Full `trace_fanin` resolves these to `[]` for unsigned and does not invent bits.
   Not introduced by this commit.
5. **Unknown shift stays unknown**: `assign y = a << idx;` → `_expr_source_bits` returns
   `None` for every destination bit and `_expr_dst_bits` returns `None` for every source bit;
   full `trace_fanin` degrades to the bus-level `['top.a', 'top.idx']`, never a fabricated
   bit-level dependency. No loop/exception introduced — both new helpers are pure arithmetic
   with `int()` guarded by `isinstance(width, (tuple, list))`.
6. **Tests are genuinely revert-sensitive**: running the 14 assertions of the new test
   against a `/tmp` copy with the parent `signal.py` yields 14/14 FAIL (e.g. `<<`: y[7] gives
   `a[5]` not `a[7]`; mixed: y[2] gives `a[0]` not `a[7]`); against HEAD, 7/7 pytest pass.
7. **P198 regressions clean**: `test_p198_4_concat_layout.py` + `test_p198_11_concat_ir.py`
   → 17 passed; full canonical suite → **3338 passed, 0 failed, 123 deselected, 35 subtests**
   (409.96 s), matching the docs updates.
8. **Full gate green**: `bash tools/run_gates.sh` ends `All checks passed!`, including
   `privacy: PASS (no private assets / absolute home paths)`, docs strict, plan, command
   surface, semantic-regex, core-except, no-telemetry, lint/CC ratchet.
9. **Independence**: reviewer is a separate session from the implementer; the diff, not the
   commit summary, was inspected; findings were reproduced with executable probes; this
