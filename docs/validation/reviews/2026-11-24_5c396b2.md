## Verdict

**FAIL — 1 × P1 (blocking), 2 × P2.** Rework + independent re-audit required before merge/release.
The implementation is correct for the trivial single-top-module fixture, but the core
graph-linkage step (`_attach_expression_ir`) uses the **module definition name** instead of
the **instance path**, so continuous-assign IR is not attached to any DRIVER edge for
submodule instances (including multiple instances of one module). The new tests only
exercise the case where instance path == definition name, so they give false confidence.

## Findings

### F1 — P1 — IR never attaches to submodule / multi-instance DRIVER edges; aid collapses instances
**Files:** `src/sv_query/trace/core/graph_builder.py:220`, `:228-240`; `src/sv_query/trace/core/semantic/modules.py:346-368`
**Detail:**
- `_attach_expression_ir` sets `module_name = self.adapter.get_module_name(module)`, which
  returns the **definition** name (e.g. `sub`), and builds `target = f"{module_name}.{lhs_name}"`
  (`graph_builder.py:220`). It then matches `self.graph._edge_data_for_dst(target)` (`:236`).
- Graph edge `dst` ids are **instance paths** (e.g. `top.u0.y`). `driver_extractor.py:1317`
  explicitly uses `module_name = inst_path`, and `_configure_instance_paths`
  (`graph_builder.py:698-822`) builds paths like `top.u0`. Only for a top-level instance whose
  name equals its definition name (`top`) does `def_name.signal` coincide with the edge id.
- Consequence 1: for a submodule instance, the assignment is stored but **no edge gets
  `expr_id`/`assignment_id`** — later IR consumers (P198.5) will see "no IR" / unknown on
  exactly the hierarchical designs this project targets.
- Consequence 2: with N instances of one module, `aid = sha256(f"{module_name}:{lhs}:...")`
  (`:215-217`) contains no instance component, so all N elaborated assignments collapse to
  one table entry; even the intended "one assignment, many leaf edges" linkage cannot be
  expressed per instance.

**Repro (read-only, /tmp only):**
```python
from sv_query.trace.unified_tracer import UnifiedTracer
sv = """
module sub(input logic [7:0] a, output logic [9:0] y);
  assign y = a << 4'd2;
endmodule
module top(input logic [7:0] a0, a1, output logic [9:0] y0, y1);
  sub u0(.a(a0), .y(y0));
  sub u1(.a(a1), .y(y1));
endmodule
"""
g = UnifiedTracer(sources={"m.sv": sv}, log_level="ERROR").build_graph()
print(list(g.assignments))                       # ['assign:14b1ec51a1ea43ff']  (1, not 2)
for (s,d),es in g._edge_data.items():
    for e in es:
        if e.kind.name=="DRIVER": print(s,d,repr(e.expr_id),repr(e.assignment_id))
# top.u0.a -> top.u0.y  '' ''      <-- no IR
# top.u1.a -> top.u1.y  '' ''      <-- no IR
```
Observed: `assignments` has 1 entry; both DRIVER edges have empty refs.
Also verified for a single submodule instance `foo u0(...)`: its DRIVER edge has empty refs.

**Fix:** enumerate the same `(instance_path, instance_symbol)` pairs used by the driver
extractor (expose them from `_configure_instance_paths` / GraphBuilder), pass
`module_name = instance_path` into `_assignment_ir`, and include `instance_path` in the `aid`
hash so each instance has its own assignment. `target` then becomes the real edge id
(`top.u0.y`), matching the graph.

**Test gap:** `sim/tests/unit/test_p198_3_graph_ir.py` uses only `module top ... assign y = ...`
where instance path == definition name. Add a multi-instance test asserting 2 distinct aids
and non-empty, instance-correct `expr_id`/`assignment_id` on every DRIVER edge.

### F2 — P2 — dangling/stale edge refs accepted on snapshot load without validation
**Files:** `src/sv_query/trace/core/graph/models.py:875-876`, `:885-896`
**Detail:** `from_dict` copies `expr_id`/`assignment_id` from each edge dict verbatim and
restores the store/assignments separately, with no cross-check. A snapshot whose edge refs a
non-existent `expr_id`/`assignment_id` loads cleanly; `get_expression()` then raises a bare
`KeyError` only if/when someone looks it up. Violates iron-rule 2 (failure must be explicit)
and §6 "no stale/mismatched refs". Partial payloads (`expression_store` present but
`assignments` missing) also silently drop the assignment table.

**Repro:** take `graph.to_dict()`, set a DRIVER edge's `expr_id="expr:missing"`,
`assignment_id="assign:missing"`, call `SignalGraph.from_dict(d)` — it succeeds; the dangling
id sits on the edge until `get_expression()` is called.

**Fix:** after restoring the store/assignments, validate every non-empty edge ref resolves;
raise `ValueError("SignalGraph.from_dict: dangling expr_id/assignment_id ...")` otherwise.
Require both IR keys to be present-or-absent together.

**Test gap:** no malformed-ref / stale-ref snapshot test.

## What is correct (to avoid false positives)

Verified by command/test, not by reading the diff alone:

1. **Wiring / serialization / one-per-assignment:** For the top module,
   `graph.assignments` has 1 entry, DRIVER edge carries matching `expr_id` == `rhs.expr_id`
   and `assignment_id`; `graph.get_expression(edge.expr_id).op == "ShiftLeft"`. Two continuous
   assigns in one module → two table entries, procedural `always_ff` assign → no entry,
   nets/instances → no entries.
2. **Flat wire format (IR_VERSION 2):** `ExpressionStore.to_dict()` writes each expression once;
   all `children` are `expr:<hash>` strings; `version == 2`. `from_dict` validates missing child
   (`missing expression`), cycle (`cycle at ...`), id mismatch (`id mismatch ...`), non-string
   ids, unknown fields, and unsupported version. `AssignmentExpr.from_ref_dict` validates
   missing lhs/rhs/condition refs. No subtree duplication observed (5 nodes for `a << 4'd2`).
3. **Old data:** stripping `expression_store`/`assignments` and the two edge keys from a fresh
   snapshot yields `assignments == {}`, empty store, and empty edge refs — no false references.
4. **Cache:** `CACHE_VERSION` bumped 3.1→3.2; `unified_tracer.py:458-462` puts
   `{"graph_data": self._graph.to_dict(), ...}` so IR is in the payload; `get_by_key`
   rejects mismatched version/hash. Manual two-build run: `miss` then `hit`, hydrated graph has
   identical aid, edge `expr_id`, and store size. BuildIdentity key/manifest include
   `cache_schema` (= CACHE_VERSION).
5. **Snapshot round-trip:** `to_dict → json → from_dict` preserves assignments keys, lhs/rhs
   content, store size, and edge `expr_id`/`assignment_id`. No cross-instance false match was
   found in the scenarios tested; the observed defect is under-attachment, not over-attachment.
   Pipeline order is safe: `expression_ir` declares `requires={"edges"}` and is last in
   declaration order, so it runs after all edge-mutating stages; dedup in `add_trace_edge`
   now includes `expr_id`/`assignment_id`.
6. **Tests/revert:** 16 targeted tests pass; full unit suite `1408 passed, 2 skipped`. Reverting
   `IR_VERSION` 2→1 makes the modified `test_expression_ir.py` version assertions fail
   (verified by loading the parent module: v1 accepted, v2 rejected). Reverting graph wiring
   or CACHE_VERSION would respectively break `test_p198_3_graph_ir.py` and
   `test_p194_2a_build_identity.py`.
