## Findings

### P1-1 — Unary minus/plus not mapped; `-a` becomes `Unknown` instead of `Neg`

- Location: `src/sv_query/trace/core/expression_builder.py:17-20` (`_UNARY_OPS`),
  consumed at `:54`; emitted by `:93-98` (`_unary`).
- Cause: dict keys are `logicalnot/bitwisenot/negate/unaryminus/unaryplus`.
  pyslang v11 enum `.name` values are `LogicalNot/BitwiseNot/Minus/Plus/BitwiseAnd/...`.
  `_op_name()` lowercases `.name` → `minus`, `plus`, which are absent from the dict.
- Repro (read-only probe, real semantic AST):
  ```
  assign y = -a;   # UnaryOperator.Minus
  build_expr(rhs) -> Expr(op='Unknown', reason='unsupported unary operator <UnaryOperator.Minus: 1>')
  ```
  `!a`→`Not`, `~a`→`Not` work; `-a` and `+a` do not. §5 requires `Unary → Not/Neg`.
- Impact: silent **unknown inflation** for a fully resolvable, common operator.
  `OPS`/`map_bit` (§8) already provide `Neg`; this is a pure mapping bug, not an
  unsupported construct.
- Fix: add `"minus": "Neg"` (and optionally `"plus": ""`/unary-plus passthrough) to
  `_UNARY_OPS`, aligned to pyslang v11 enum names (`Minus`, `Plus`). Keep the old
  keys harmlessly; do not guess — assert against the enum `.name` in a test.
- Test gap: **no unary test at all** in the new test file. Add `assign y = -a;`
  asserting `op == "Neg"` and one operand; also assert `!a`/`~a` → `Not`. A revert
  of the mapping entries must make this test fail.

### P1-2 — Constant single-bit `ElementSelect` loses its bit range

- Location: `src/sv_query/trace/core/expression_builder.py:121-134` (`_select`),
  specifically `:124-125` and `:127-131`.
- Cause: ElementSelect nodes expose `.value` (base) and `.selector` (index), but no
  `.right`. Code sets `msb = left or selector` (OK) but `lsb = node.right` → `None`,
  so `bit_range` is never built for element selects.
- Repro (real semantic AST):
  ```
  assign ext = a[3];
  -> Cast(Slice(width=1, bit_range=None, reason='dynamic or unresolved select',
                children=(SignalRef('a'),)))
  ```
  The selector value `3` is available (`node.selector.value == 3`) and `int()`-able,
  yet the IR reports it unresolved. §5 requires `ElementSelect → Slice/SignalRef with
  bit range`; §8 `Slice → adjust index` cannot work with `bit_range=None`.
  (RangeSelect works: `a[7:4]` → `bit_range=(7,4)`, verified.)
- Fix: when `node.right`/`lsb` is absent but `selector` is a constant, set
  `bit_range=(int(selector.value), int(selector.value))`; keep `Unknown` reason only
  for genuinely dynamic selectors.
- Test gap: no ElementSelect test; the concat test checks only `[c.op] == ['Slice','Slice']`
  and never asserts `bit_range`. Add (a) `assign ext = a[3];` asserting
  `bit_range == (3,3)` and empty reason, (b) `assign ext = a[7:4];` asserting
  `bit_range == (7,4)`, and (c) a dynamic `a[i]` asserting explicit unknown.

### P2-1 — Ordinary calls discard name/args; contract asks for `Call(name, args)`

- Location: `expression_builder.py:137-144` (`_call`), `:143-144`.
- `Call` node stores width/signed and a `reason` string containing the function name;
  `signal` is empty and `children` is empty — arguments and a structured name are lost.
  Repro: `$clog2(a)` → `Call(width=32, signed=True, reason='function call $clog2; bit mapping unknown')`.
- The bit-mapping-unknown decision is correct and explicit (no fabricated mapping),
  so this is representational debt against §5's `Call(name, args)` (affects future
  P198.6 const/function extraction). Fix: encode name in `signal` and append arg
  subtrees as `children`, or extend the IR with explicit name/args fields in a
  schema-bumped change. Add a test asserting the name and args survive.

### P2-2 — Coverage gaps: nested concat, unsupported kind, full binary-op matrix

- New tests cover shift+literal, X/Z literal, flat two-element concat (both sides),
  ternary, `$signed`/Conversion, and `$clog2` call. Not covered: nested concat
  (`{a,{b,c}}`), an unsupported expression kind → `Unknown` with reason (e.g. `==`,
  real literal), unary operators (see P1-1), `Mul/Div/Mod/And/Or/Xor` mappings, and
  `$unsigned` → `Cast`. The suite would fail on a wholesale revert (import of the new
  module) and on reverting the shift/concat/ternary/call branches, but most individual
  mappings are unguarded. Add matrix tests so every `_BIN_OPS`/`_UNARY_OPS` entry and
  the `Unknown` fall-through are pinned.

## Verification of the 8 requested points

1. **Semantic AST only / no old ExpressionTree fallback** — PASS. `build_expr` consumes
   pyslang `Expression` nodes from `ContinuousAssignSymbol.assignment.left/right`, using
   `.kind`, `.type`, `.value`, `.left/.right/.operand/.operands/.selector`, etc. No import
   of `ExpressionTree`/`expr_tree_builder`, no source-text/regex path, no fallback. The
   module is not imported by any production file (only the new test), so graph/query are
   unchanged.
2. **Mappings** — IntegerLiteral (`str(value)`, X/Z preserved): PASS. NamedValue: PASS.
   Binary: arithmetic/bitwise/shift all map correctly with left/right order and
   `ShiftLeft`/`ShiftRight` direction (enum `.name` verified): PASS. Unary: **FAIL (P1-1)**.
   Conversion→Cast: PASS. Concatenation: PASS. Conditional (condition from
   `conditions[0].expr`): PASS — `en ? a : b` yields `Ternary(SignalRef('en'), a, b)`.
   ElementSelect/RangeSelect: **FAIL (P1-2)** for ElementSelect; RangeSelect PASS.
   Call: PASS with caveat P2-1.
3. **`$signed`/`$unsigned` → Cast; ordinary calls explicit Call with unknown bit mapping,
   not fabricated** — PASS (with P2-1). Verified `subroutineName` is `$clog2`/`$signed`/
   `$unsigned` on real `CallExpression` nodes; `$signed`/`$unsigned` → `Cast`, `$clog2`
   → `Call` with reason "...bit mapping unknown" and no invented edges.
4. **Width/signedness from semantic type; missing width stays None** — PASS. `_type_info`
   reads `.type.bitWidth`/`.type.isSigned` (e.g. `bw=10` for y-typed nodes, `bw=4` for
   shift literals), returns `(None, False)` when type/bitWidth absent; propagated to
   every emitted node.
5. **LHS concat + RHS concat both retained; ternary condition real signal** — PASS.
   `{y[9:5], y[4:0]} = {a[7:4], b[3:0]}` → `Concat` on both sides with two `Slice`
   children each; condition is `SignalRef('en')`, not a constant/string.
6. **Unsupported kinds → Unknown with reason; no silent guess** — PASS. Unsupported
   binary/unary operators and unknown `.kind` fall through to `Expr(op='Unknown', reason=...)`;
   dynamic selects carry an explicit reason. Verified `a && b`/`a == b` → Unknown.
   (`Unknown` nodes are validation-safe: `Expr.__post_init__` requires a non-empty reason.)
7. **Tests use real semantic AST; revert sensitivity; gaps** — PARTIAL. Tests call
   `build_expr` on genuine pyslang nodes via `UnifiedTracer`, so they are not vacuous and
   would fail on removal/revert of the builder. Gaps: select bit ranges, nested concat,
   unary ops, unsupported kind — see P1-1/P1-2/P2-2.
8. **Full suite / gates / no graph-query change** — PASS. Independently ran the canonical

## What is correct (avoid false positives)

- No syntax-token/regex/string fallback anywhere in the builder; it is a genuine
  semantic-AST consumer. No `except: pass`.
- `str(SVInt)` preserves four-state text (`4'd2` → `4'b10`, `4'dx` → `4'bxxxx`) — no
  X/Z→0 coercion.

  `$signed/$unsigned`, become `Cast`; tests intentionally `_unwrap_cast` around them.

  `ShiftLeft`/`ShiftRight`) are correct; `ShiftLeft`/`ShiftRight` were properly added
  to `OPS` and to the contract text.
- Ternary `predicate` fallback to `conditions[0].expr` works on v11.
- `signal_resolver` is a pure optional callback; unresolved names are preserved.
- All emitted nodes are `Expr.__post_init__`-valid; `Unknown` always has a reason.

  `verified` claim); P198.3–P198.6 remain 待做.
