## Findings

### P1-1 — inline detection short-circuits on non-inline semantic op; original audit repro still reports `complete`

**File:** `src/sv_query/trace/core/graph/analyzer/controlflow_analyzer.py:219-236`
(`_looks_like_inline_condition` / `_label_unmodeled_inline`).

The new code:

```python
op = str(getattr(getattr(edge, "source", None), "op", "") or "")
if op:
    return op in cls._INLINE_OPS      # <-- returns False for BinaryAnd/Or/Xor/Add/...
if not expr:
    return False
return bool(re.search(r"(==|!=|<=|>=|&&|\|\||\?|\bcase\b)", expr))
```

When an input edge has a **non-inline** semantic op (e.g. `BinaryAnd`), the
function returns `False` immediately and never examines the expression. A
comparison nested under a bitwise/arithmetic operator is therefore missed,
even though the semantic metadata already records it (`source.inner_ops =
["=="]`) and the expression string contains `==`.

**Repro (exact shape from `docs/validation/P1945_AUDIT_2026-11-23.md` P1-2):**

```systemverilog
module top(input logic en, a, b, input logic [3:0] state_q, output logic q);
  localparam logic [3:0] IDLE = 4'd0;
  always_comb begin if (en) q = a; else q = b; end
  assign q = a & (state_q == IDLE);
endmodule
```

- Current HEAD: `condition_status="complete"`, `warnings=[]`
- Expected per C-62 / USER_GUIDE_EN: `partial` + warning

**Regression (pure inline, same nested shape):**

```systemverilog
assign y = a & (state_q == IDLE);
```

- Parent `bca8e0d1`: `not_modeled` + warning (regex fallback saw `==`)
- Current HEAD: `complete`, no warnings  <-- **introduced by this commit**

Breadth confirmed: `a | (s == IDLE)`, `a ^ (s == IDLE)`, and
`a + (s == IDLE)` all return `complete` on HEAD, while the direct
`(s == IDLE)` correctly returns `not_modeled`. Root cause: the top-level
`source.op` is `BinaryAnd`/`BinaryOr`/`BinaryXor`/`Add` and the new early
`return` suppresses both the `source.inner_ops` signal and the regex
fallback that the parent used.

**Impact:** silent false "complete" (unknown control presented as modeled),
the exact P1-2 that P194.5f claims to close; `C-62` is therefore marked
`verified` on an inaccurate basis and `docs/USER_GUIDE_EN.md:226-230` is false
for this input shape.

**Fix required:** do not short-circuit on a non-inline `op`; consult semantic
`source.inner_ops` (which already carries `==`/`!=`/comparison ops) and/or
retain the expression fallback for all ops. Add a regression test for a
comparison nested under bitwise/logical/arithmetic operators, in both pure-inline
and mixed if/case + inline forms. Re-audit required.
