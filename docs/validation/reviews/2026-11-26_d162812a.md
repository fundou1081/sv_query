## Verification results

### 1. In-range out-of-graph bit parity — PASS

Real `UnifiedTracer` + `build_graph`, fixture from the new test
(`assign y = 8'h00; assign y[3] = a[3];`), `top.y[2]` is **not** in the graph:

| API | drivers |
|---|---|
| `trace_fanin("top.y[2]")` | `["1'b0"]` |
| `trace_fanin_detailed("top.y[2]")` | `["1'b0"]` |
| `trace_detailed("top.y[2]").drivers` | `["1'b0"]` |

Driver-id sets of `trace_detailed` and `trace_fanin_detailed` are identical
(`parity=True` on every probed query). The fix works because `trace_detailed`
(`signal.py:2180-2188`) no longer returns early on `not in_graph` when
`_bit_in_bus_range` is true, and delegates to `trace_fanin_detailed`; `_trace_missing_node`
(`signal.py:292`) then performs the existing parent-bus bit-filter fallback.
Confidence is `high` for the literal-driven bit — consistent with the in-graph
precise-bit case asserted by `test_p197_16_provenance.py::test_precise_bit_and_literal_are_high_confidence`,
so this is parity, not unknown inflation. Parity also holds for `top.y[0]`,
`top.y[7]`, the literal-only/bit-only/concat fixtures, and a coarse-parent fixture
(`assign y = a; assign y[3] = 1'b0;` → `top.y[2]` gives `['top.a']`, `confidence=low`
on **both** detailed paths, matching C-75).

## What is correct (to avoid false positives)

- The diff is confined to one query module, one new test and count/state docs; no
  graph construction, IR, cache, snapshot, session, verification or CLI code changed.
- The new guard is based on graph metadata (`node.width`) via `_bit_index_of` and
  `get_node`, not on name-prefix guesses; part-selects (`[a:b]`) and non-numeric
  brackets keep their locked empty answer.
- `trace_detailed` and `trace_fanin_detailed` now agree by construction (the
  former delegates to the latter for valid in-range bits), so the P197.18 N3
  asymmetry is actually removed, not merely hidden.
- No fabricated graph node/edge: `trace_fanin_detailed` still builds `DriverInfo`
  from `trace_fanin` results; `_driver_detail_metadata` only reads edges/metadata.
- Helper extraction is a pure refactor: identical snapshots across all probed
  in-graph cases, including conditional/clocked edges.
- New tests assert exact sets (not `in (...)`), exercise the real repro fixture,
  and fail on the parent.
