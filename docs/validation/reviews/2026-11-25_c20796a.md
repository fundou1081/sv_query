## 6. Findings (residual P2 — none blocking)

**P2-1 — Duplicated CLI `is_verified` recomputation uses raw substring.**
`src/sv_query/cli/core/semantic/trace_evidence.py:190-192`:
`leaf = signal.rsplit(".",1)[-1]; ev_dict["is_verified"] = leaf in source;
credibility_score = 1.0 if leaf in source else 0.2`. The core fix does not reach
this path; CLI recomputes `is_verified` independently of
`Evidence.matches_signal_name` (iron rule 8: one semantic, one implementation).
Today `source` is returned by `find_functional_assignment` and therefore passed
`line_is_lhs` (whole-token LHS regex), so `leaf in source` cannot be triggered by
`metadata` in practice — verified: the `top.data` / `metadata` CLI probe above is
`False`. Residual risk is latent: if `_functional_line_for` ever returns an
unguarded line, the original false positive returns, and CLI/core scoring rules
diverge. Fix: call `signal_token_present(signal, source)` here, or drop the
recompute and derive from the core `Evidence`. Test gap: no unit test pins
CLI/core score agreement for a substring-only line.

**P2-2 — Sibling RHS-substring false positive remains in `matches_source_expr`.**
`src/sv_query/trace/core/trace_evidence.py:101` still uses
`self.source_expr in snippet.text`. Repro: `Evidence(signal="top.d",
source_expr="d", enclosing_assign=<"assign metadata = x;">)` gives
`matches_signal_name=False` but `matches_source_expr=True`, `is_verified=True`,
`credibility_score=0.6`. Same false-verified class as P1-c but via the RHS
cross-validation side. Out of the stated LHS scope, but relevant to "evidence
credibility"; requires a short `source_expr` to manifest. Fix: apply whole-token
matching to `source_expr` too. Test gap: none for RHS substring cases.

**P2-3 — Compound reset-like data tokens can suppress a functional assignment.**
Because `&&`/`||` no longer short-circuit `is_reset_condition`, a condition such
as `check_reset_status && valid` (token `reset` preceded by `_`) now returns `True`;
`_active_reset_branch` gives `True` (no `!`, no literal, token not active-low), so
the guarded functional assignment can be skipped as a reset branch. This class
existed before for simple conditions and is inherent to the documented textual
heuristic; the change broadens it to compound conditions. Also, despite the code
comment "assignment/declaration is not a condition", bare declarations without `=`
(`logic reset;`) still return `True`; reachability is limited because callers pass
`if (...)` bodies or assignment lines, and treating a declaration/reset line as
"reset" merely triggers fallback to a functional line. Severity P2 (latent,
naming-dependent), not a demonstrated wrong answer in the canonical fixtures.
Fix if desired: require reset token to be a standalone/active-low signal rather
than any `reset\w*` identifier, and reword the comment to say "assignment".

**P2-4 — Privacy-redaction edit degraded a prior review artifact's factual text.**
The prior review's path examples were replaced with placeholders, which made its
sentence self-referential and inaccurate; the redaction itself is complete
(`check_privacy.py` PASS). The historical record should state that the two home
paths were redacted without reproducing them, while preserving the verdict and
findings.
