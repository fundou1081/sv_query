## 2. Finding-by-finding verification

### 2.1 Slice/Cast/Ternary fanin/fanout correctness

Read-only probe `/tmp/p1989_probe.py` built graphs from real SV text via `UnifiedTracer` (pyslang semantic AST), removed legacy text (`edge.expression="GARBAGE"; edge.source=None`) and exercised the IR path directly:

| shape | IR root op | fanin (with legacy removed) | fanout |
|---|---|---|---|
| `y = a[3:0]` | Cast→Slice | y0→a0, y2→a2 (correct) | a0→y0, a2→y2 |
| `y = $signed(a[3:0])` | Cast→Slice | y4..7→a3 (sign bit, correct) | a3→y3..y7 (sign extension) |
| `y = sel ? a : b` | Ternary | a-edge→a[bit]; b-edge→b[bit] (correct per-edge filtering) | both→y[bit] |
| `y = a << 2` | ShiftLeft | unchanged | unchanged |

`bit_mapping.py` handlers are present and correct for all three ops: `_res_slice/_in_slice` use `min(bit_range)`/`lo..hi`; `_res_cast/_in_cast` handle signed extension via `_cast_extends_sign`, and explicitly return `None` for literal/unsigned extension so legacy owns constant bits; `_res_ternary/_in_ternary` map children[1]/children[2] and propagate `None` if either branch is unmappable. Condition (children[0]) is not treated as a data bit — consistent with iron-rule 13 (`BRANCH_CONDITION` is a control edge; probe confirmed the ternary-select edge has no `expr_id`).

**No false legacy fallback**: for IR-enabled edges the mapper result is used directly; `if mapped is None: return None` (signal.py:774-775, 925-926) preserves the P198.5 F2 fix. Re-verified via `/tmp/p1989_revert.py`: forcing the gate back to shift-only makes both new tests fail with `AssertionError`, i.e. they genuinely exercise the IR route, not the legacy path.

**C1 — P2 — Test-coverage thinness for the newly enabled ops and one untested delta.**
`sim/tests/unit/test_p198_9_ir_shapes.py` has only 2 tests: slice fanin and ternary fanin. There is **no Cast route test**, **no fanout test for any of Slice/Cast/Ternary**, and **no CLI/session parity test for the new shapes** (the existing `test_p198_5_cli_session_parity.py` covers shift only). Evidence: (a) `/tmp/rmonkey_gate.py` (revert op gate to shift-only) on all relevant regression suites → **82 passed, 0 failed** — no canonical test depends on the new op enablement; only the 2 new unit tests do; (b) `/tmp/rmonkey_srcbits.py` (revert only the `ir.width == 1` source-bit condition to the WIP's unconditional relative-bit form) → full canonical still **3306 passed** — that runtime delta has **zero** test coverage. Manual analysis indicates the target form is semantically correct (relative-bit applies only to width-1 bit nodes; for a slice dst the incoming `bit_filter` is already relative), while the WIP form would mis-map a relative slice-bit index to a negative out_bit; no canonical case reaches it because bit-slice expansion supplies the answer first. The implementation is nonetheless correct under all probed cases (§2.1), so this is coverage debt, not a demonstrated wrong answer. Fix: add a Cast-wrapped fanin test, Slice/Cast/Ternary fanout tests, and a case that exercises the `ir.width==1` branch (and optionally CLI/session parity) under P198.9/P198.11 follow-up.
