## 2. Findings

### F1 — P1 — name/dot-count heuristic silently suppresses genuine out-of-bounds (false verified)

**Location**: `src/sv_query/cli/core/semantic/verify.py:242-254` (`_has_deeper_same_leaf`),
called at `:315-316` inside the parent-range OOB branch of `_check_bit_mapping`.

The suppression fires when **any** node in the graph (a) has a strictly greater `.` count than
the node under check and (b) has the same leaf name after stripping the bracketed bit suffix.
It does **not** require the deeper node to be a bit-select, to share the same bit index/range,
to be connected to the same elaborated net, or even to be in the same instance branch. This is
precisely a name-based correctness guess / node-id prefix-suffix guess, which
CODE_REVIEW_PROTOCOL §3.1 forbids, and it produces a silent `verified=true` on a real violation
(the protocol's P1 "false verified" case).

**Repro (all read-only, `_check_bit_mapping(g, None)`, parent width `(0,0)`, child bit 3 or 1):**

| Case | Graph | Result |
|---|---|---|
| B | genuine OOB `top.bus[3]` + unrelated deeper 8-bit net `top.sub.bus` (same leaf) | `pass`, `violations: []` — **genuine OOB suppressed by a non-bit net** |
| C | genuine OOB `top.bus[3]` + deeper `top.sub.bus[7]` (same leaf, different index) | `pass`, `violations: []` — **suppressed by an unrelated bit node** |
| F | genuine OOB `top.a.bus[1]` + OOB `top.b.bus[1]` + a shadow only under `top.b.u.bus` | `pass`, `violations: []` — **shadow in instance `b` masks a genuine OOB in sibling instance `a` (cross-instance contamination)** |

Case E (the intended SERV shape: shallow `top.rdata0[1:1]` shadowed by a deeper
`top.u.rdata0[1:1]`) is correctly suppressed, so the fix does address the reported false
positive — but it over-generalizes far beyond that shape.

**Impact**: `verify consistency --checks bit` can report `verified:true, total_violations:0`
while an internally inconsistent bit node exists. Repeated leaf names (`data`, `bus`, `valid`,
`rdata0`) across hierarchy levels are normal, so the trigger is reachable in ordinary designs;
the check's whole purpose is to catch exactly these walker artifact nodes.

**Fix required**: replace the leaf-name/dot-count test with a structural test — suppress only
when the deeper node is the *authoritative* bit-select child of the same elaborated net, e.g.
require an actual instance-path/ancestry relationship on the node IDs, that the deeper node is
a bit node, and that its `parent_bit_start/end` (or `bit_range`) matches the shallow node's.
Do not suppress on same-leaf-name + depth alone.

**Test gap**: no regression covers cases B/C/F. The only new test
(`test_p194_5_17_bit_scope.py::test_nested_peer_suppresses_top_shadow_violation`) locks the
suppression; the existing OOB test has no deeper node. Add tests asserting a genuine OOB is
still reported when an unrelated deeper same-leaf net/bit, or a sibling-instance shadow, exists.
