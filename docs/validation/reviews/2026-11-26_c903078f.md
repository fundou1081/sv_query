## Verification results

### 1. Confidence provenance — PASS

`SignalTracer._confidence` (`signal.py:44-52`) now returns:

- `uncertain` when there are no drivers (unchanged, iron rule 3 preserved);
- `low` when the queried id is a bit select, the node is **not** an
  `array_element`, and at least one driver id lacks `[` (coarse parent bus);
- `high` otherwise.

Both call sites were updated consistently: `trace()` (`signal.py:67`) and
`trace_detailed()` (`signal.py:2182-2183`, passing `d.node`).

Repro (library API, fresh tracer per case, `use_cache=False`):

| fixture | query | drivers | confidence |
|---|---|---|---|
| `assign y = a; assign y[3] = 1'b0;` | `top.y[3]` | `1'b0`, `top.a` | **low** |
| same | `top.y` | `top.a`, `1'b0` | high |
| `assign y[3] = a[3]; assign y[7:4]=a[7:4]; ...` | `top.y[3]` | `top.a[3]` | **high** |
| `assign y = 8'h00; assign y[3] = a[3];` | `top.y[3]` | `top.a[3]` | high |
| `assign y = a;` only | `top.y[3]` | none | uncertain |
| `module top(output logic [7:0] y);` | `top.y[3]` | none | uncertain |

`trace()` and `trace_detailed()` agree in every case above. Precise-bit-high,
bus-high, coarse-parent-low and empty-uncertain are all confirmed.

### 2. Instances depth relative to root/top — PASS

New shared helper `instance_within_depth(path, root, depth)`
(`architecture.py:41-49`) delegates from CLI `_depth_ok`
(`cli/core/semantic/instances.py:70-72`) and session `instances()`
(`query/session_ops.py:101-103`). The old CLI dot-count path and the old
session `full_path.count(".")` path are gone.

Empirical nested fixture (`top.u_mid.u_leaf`):

- CLI `--depth 1` → `["top.u_mid"]`; `--depth 2` → both instances.
- Session `instances(depth=1)` → `["top.u_mid"]`; `depth=2` → both;
  `depth=None` → both. CLI and session agree.
- With `--module top.u_mid --depth 1` both surfaces return the module and its
  direct child, as before.

No dot-count bug remains for the no-root case: previously `top.u` had 1 dot
and was excluded at `depth=1`; now it is correctly treated as one level below
top and included.

### 3. Cache singleton env rebuild — PASS

`get_cache()` (`ast_cache.py:554-563`) reads `SVQ_CACHE_DIR` on every call and
rebuilds only when the cached instance is **managed** and the env string
changed. `ASTCache.__init__` sets `_managed=False`; only `get_cache()` sets it
`True`.

Repro (in-process):

- `SVQ_CACHE_DIR=a` → get_cache → instance X, dir `a`, managed=True.
- same env again → same instance X (no spurious rebuild).
- `SVQ_CACHE_DIR=b` → new instance Y, dir `b`, managed=True, `first is not second`.
- Manually assigned `ASTCache(cache_dir=a)` → `_managed=False`; changing env
  to `a`/unsetting env returns the **same manual instance** (pinned).

No cache regression: `test_bit_bridge_cache`, `test_p197_7_mig_cache`,
`test_p194_2a_build_identity`, `test_p195_2_capability_enforcement` all pass;
`tools/check_privacy.py`, `check_core_except.py`, `check_no_telemetry.py`,
`check_except_pass.py`, `check_repo_hygiene.py` pass.
