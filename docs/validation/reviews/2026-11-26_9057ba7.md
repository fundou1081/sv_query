## Findings

### N1 — P1 (NEW, introduced by rework): descending part-select destinations map IR bits in reverse

- **file:line**: `src/sv_query/trace/core/query/signal.py:434-458` (`_slice_is_ascending`,
  `_dst_ir_bit`); called from `:822-833` (`_expr_source_bits`).
- **Root cause**: `_slice_is_ascending` first reads `parent_bit_start/parent_bit_end`,
  which the graph normalizes to `min/max` for **all** part-selects (e.g. `y[5:2]`
  and `y[2:5]` both give `start=2, end=5`). `start < end` is therefore always true,
  so every slice is treated as ascending and `_dst_ir_bit` returns
  `width-1-want_bit`. That is only correct when the **parent declaration** is
  ascending (`[0:7]`); for the far more common descending declaration (`[7:0]`)
  the correct offset is `want_bit`.
- **Repro (HEAD, public CLI)**:
  ```systemverilog
  module top(input logic [7:0] a, output logic [7:0] y);
    assign y[5:2] = a << 2;
  endmodule
  ```
  `run_cli.py trace fanin 'top.y[4]' -f <sv> --json` → `drivers: []`
  (`precision: unknown`, `bit_fallback: true`). `top.y[5]` → `top.a` (false source).
  Parent `1f39223a` and FAIL commit `5c5e9d8b` → `top.y[4]`, `top.y[5]` = `top.a`
  (correct, bit-level `a[0]`, `a[1]`), `top.y[2]`, `top.y[3]` = `[]` (correct zero-fill).
- **Ground truth**: Verilator 5.048 simulation with `a=8'h42` (`a[1]=1`) gives
  `y[5:2]={1,0,0,0}`; with `a=8'h09` (`a[0]=1`) gives `y[5:2]={0,1,0,0}`.
  Hence `y[5]=a[1]`, `y[4]=a[0]`, `y[3]=y[2]=0` — parent/FAIL mapping, not HEAD.
- **Impact**: silent wrong answer / dependency loss on a normal SV partial
  assignment (P1 per protocol §4). The ascending-slice test added by this commit
  masks the descending mirror case; P198.4/P198.11 stay green because they assert
  concat layout/edge structure rather than per-bit IR mapping into a descending
  **part-select** destination.
- **Fix direction**: decide the reversal from the **parent bus declaration**
  direction (or the slice's true LSB end), not from normalized `parent_bit_start/end`.
  Concretely, for `want_bit r` with slice bounds `lo=min(pbs,pbe)`, `hi=max(pbs,pbe)`:
  physical bit `p = lo + r`; IR offset = `hi - p` when the parent is declared
  ascending (`msb < lsb`), else `p - lo`. This yields `3-r` for `[0:7] y[2:5]` and
  `r` for `[7:0] y[5:2]`. A guard returning `None` when parent metadata is missing
  would also avoid silent `[]`.
- **Test gap**: add a descending part-select assertion that fails on HEAD and passes
  after the fix: `assign y[5:2] = a << 2;` with `y[7:0]`, asserting slice bits
  2→`[]`, 3→`[]`, 4→`a[0]`, 5→`a[1]`, plus a chained-bit fanin check.
