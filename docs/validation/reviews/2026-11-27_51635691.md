## Findings

### P1-1 — `disk_line()` subtracts an injected-timescale shift that was never applied

`src/sv_query/trace/core/assignment_source.py:16-22`:

```python
text = next((t for k, t in sources.items() if Path(k).name == name), "")
shift = compiled_line_shift(filename, text) if text else 0
if shift == 0 and text.lstrip().startswith("`timescale"):
    if not Path(filename).is_file():
        shift = 1          # <-- assumes injection; cannot tell original vs injected
return max(1, line - shift)
```

`compiled_line_shift()` (`source_assignment.py:218-227`) returns 0 when the on-disk file cannot be read (inline source, or bare basename not in cwd). The fallback then unconditionally sets `shift=1` whenever the *preprocessed* text starts with `` `timescale `` — but that text also starts with `` `timescale `` when the user wrote the directive themselves and `inject_default_timescale()` correctly skipped injection.

**Repro A (inline source with its own timescale):**

```python
UnifiedTracer(sources={"p.sv":
  "`timescale 1ns/1ps\n"
  "module top(input logic a, output logic y);\n"
  "  assign y = a;\n"          # disk line 3
  "endmodule\n"}, log_level="ERROR").build_graph()
# DRIVER top.a->top.y source_location.line_start == 2   (should be 3)
```

**Repro B (real filelist, bare basename, existing timescale):** strict_uart fixture, cwd = repo root:

```
fifo.sv:32: case ({push_i && !full_o, pop_i && !empty_o})
fifo.sv:33:     2'b10: count_q <= count_q + 1;
fifo.sv:34:     2'b01: count_q <= count_q - 1;
```
Target graph edges: `count_q + 1` → **line 32**, `count_q - 1` → **line 33** (both one line early). Snapshot evidence returns `source_text='count_q + 1'` at line 32. Parent had no provenance on these edges, so this is a newly introduced wrong answer.

Also confirmed with `UnifiedTracer(files=[abs_path])` on a file whose first line is `` `timescale ``: assign at line 3 reports line 2.

**Impact**: `drivers --evidence` (`trace_common.edge_evidence_dict`) and fanin/fanout evidence consume `edge.source_location` verbatim; snapshot evidence also uses it. Live `trace evidence` happens to self-correct via `_assignment_line_from_file()` text search, masking the bug on that one surface. Any source that already has a `timescale` directive — very common in real RTL and in the shipped fixtures — gets an evidence line that points at the preceding statement (condition/case header or another assignment). This is exactly the class of silent wrong answer C-78 exists to eliminate.

**Fix**: record the preprocessing line shift explicitly (e.g. have `inject_default_timescale` / `preprocess_all` return a per-source shift map, or retain the original source text in the adapter and compare) instead of inferring it from the preprocessed text. Do not guess injection from `startswith("`timescale")` when no on-disk reference is available.

**Test gap**: neither new test uses a `timescale` directive or a filelist/bare-basename source; add both an inline-with-timescale case and a filelist case and assert the exact assignment line.

### P2-1 — New/changed tests are revert-sensitive but do not cover the failing cases

`sim/tests/unit/test_p194_5_10a_assignment_provenance.py` (2 tests) and `sim/tests/cli/test_trace_snapshot.py::test_p4_evidence_from_snapshot` all fail on parent fd5b2ccd (verified: 2 unit failures + 1 snapshot failure), so they are genuine regression tests for what they assert. But they assert only "location is not None / correct line for a timescale-free inline source" and "snapshot source_text is non-empty"; they do not assert the *correct* line under timescale, filelist basenames, nested/bit-range mapping, or non-pollution of CLOCK/RESET edges. The changed snapshot assertion passes on target even though the snapshot line is off by one (P1-1).

### P2-2 — Continuous DRIVER edges from net declarations have no provenance

`assign_extractor.create_assign_edges()` handles `ContinuousAssignSymbol` only. `wire x = y;` initializers produce `assign_type="continuous"` DRIVER edges via `net_decl_extractor`, which is not wired to `_assignment_location()`. In picorv32, **490/715** continuous DRIVER edges have `source_location=None` (e.g. `dbg_mem_valid`, `mem_la_firstword` at lines 183/362). These are unconditioned, so not directly C-78, but the task statement's "continuous DRIVER edges get exact assignment source_location" is only partially satisfied.

### P2-3 — Debug-only fallbacks remain on semantic-location failures

`assign_extractor._assignment_location()` (`assign_extractor.py:72-76`) returns `None` on any exception; `always_extractor.py:841-849` logs only at debug level. On failure the post-pass in `driver_extractor.py:1358-1374` may then write a *condition* line, which conflicts with iron rules 2/3 (no silent fallback). No occurrence was observed in the probed projects, hence P2.

### P2-4 — Cache identity not bumped for changed graph semantics

`BuildIdentity.GRAPH_SEMANTICS_VERSION` remains `"2"` and `PACKAGE_VERSION` is unchanged. A cached graph built by the parent code can be reused by this code and will lack assignment provenance until a release version bump invalidates it. Consider bumping `GRAPH_SEMANTICS_VERSION` when edge semantics change.

### P2-5 — Pre-existing CLOCK/RESET location pollution is unchanged (not introduced here)

`driver_extractor.py:1358-1374` still fills `source_location` from `condition_ast` for any edge lacking one, including CLOCK/RESET edges. Example (target *and* parent): conditional `always_ff` CLOCK edge with `condition='en'` carries `p.sv:4:9` (the `else` assignment line), while the DRIVER edge correctly gets line 3. `edge_factory.py:96-97` itself correctly clears non-DRIVER locations, so this commit adds none; it remains as debt.

### Latent design note (not a finding) — ContextVar lifetime

`edge_factory._CURRENT_ASSIGNMENT` is a module-global ContextVar set at `always_extractor.py:173` and never reset. Precedence probe: explicit > ctx-tuple > ContextVar; CLOCK/RESET correctly cleared. Only `always_extractor.py:267-278` (ternary-leaf DRIVER edge) relies on the ContextVar without passing `ctx`; all other blocking/nonblocking creation sites pass `ctx`. Cross-build/cross-module leak probes (always build → function-call continuous build) found no inherited stale location. Still, the never-reset global is fragile for long-lived sessions and deserves a `token.reset()` in a `try/finally` around the always-item loop.
