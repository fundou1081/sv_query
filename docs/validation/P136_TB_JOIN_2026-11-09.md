# P136.3 TB random field → RTL snapshot candidate join

**日期**: 2026-11-09
**问题**: TB 的 `i2c_item.nakok` 与 RTL 的 `reg2hw.fdata.nakok.q` 没有一条命令连接
**结果**: 新增 `trace tb-join`，返回约束 + RTL candidates + 明确 join_status

---

## 1. 命令

```bash
sv_query trace tb-join <tb_field> \
  --filelist <tb.f> 或 -f <tb.sv> \
  --from-snapshot <rtl_snapshot> \
  --json
```

示例：

```bash
sv_query trace tb-join i2c_item.rcont \
  --filelist /tmp/i2c_dv.f \
  --from-snapshot opentitan_i2c --json
```

## 2. 输出

```json
{
  "tb_field": "i2c_item.rcont",
  "leaf": "rcont",
  "constraints": [
    {"block": "i2c_item.rcont_c", "vars": ["rcont", "stop"],
     "conditions": ["read"], "expr_count": 1}
  ],
  "join_status": "multiple_candidates",
  "rtl_candidates": [
    {"signal": "i2c.i2c_core.reg2hw.fdata.rcont", "name": "rcont", ...},
    {"signal": "i2c.reg2hw.fdata.rcont", "name": "rcont", ...}
  ],
  "note": "name-based candidate join; verify against driver/BFM/source"
}
```

`join_status`：

```text
single_candidate  只找到一个 leaf 候选
multiple_candidates  多个候选；不能静默选一个
not_found  没有候选
```

## 3. 设计原则

TB 和 RTL 是两个编译域。该命令**不宣称** name match 就是真实连接：

- 返回所有候选；
- 保留 canonical id/file/line；
- 让 agent 用 source/driver/BFM 继续确认；
- 不把 `multiple_candidates` 降级成 `single_candidate`。

## 4. I2C 实测

### rcont

```text
constraints: i2c_item.rcont_c
join_status: multiple_candidates
candidates:
  i2c.i2c_core.reg2hw.fdata.rcont
  i2c.reg2hw.fdata.rcont
  i2c.u_reg.reg2hw.fdata.rcont
```

### nakok（无 constraint）

```text
constraints: []
join_status: multiple_candidates
candidates:
  i2c.i2c_core.reg2hw.fdata.nakok
  i2c.reg2hw.fdata.nakok
  i2c.u_reg.reg2hw.fdata.nakok
```

未受约束的 random field 也可以 join（constraints 为空），不会强行报 not_found。

## 5. 边界

- name-based，不是 driver/BFM 映射；
- 不解析 UVM sequence/RAL 的 register 映射；
- 多层级 duplicate 候选很常见；
- 需要人工/source 确认；
- 不是“TB 字段到 RTL 的证明”。
