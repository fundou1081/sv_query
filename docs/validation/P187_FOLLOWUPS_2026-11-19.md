# P187 后续建议 — bit-level 查询面与证据完整性

> **状态**: 建议登记，不是已批准计划，不是已实现能力。
> **来源**: [P187 CVA6 value cases](P187_VALUE_CASES_CVA6_2026-11-19.md)
> **日期**: 2026-11-19

## 1. 结论

P187 说明核心图/查询能力能命中真实信号级缺陷，但当前 **bit-level 查询面不够产品化**：

```text
bus-level query 漏掉 bit-select 缺陷
dataflow 对 bit endpoint 可能静默 false
evidence 可能缺 source location
```

下面按优先级记录候选改进，不改变当前 CLI 行为。

## 2. P0 — bit-select 查询可用性

### 问题

`drivers lsu_dtlb_ppn_o` 只返回总线级 driver；C2 的两处位选缺陷不可见。必须手工：

```text
graph nodes --match lsu_dtlb_ppn_o
→ 找到 bit node
→ drivers '<bit-node>' --evidence
```

缺点是 agent 需要先知道这个工作流，且 bit node id 很长。

### 候选改动

- `drivers <bus> --bits` / `--expand-bits`：返回总线 driver + 相关 bit-select drivers；
- 或在 bus result 中增加 `bit_nodes` / `has_bit_select_drivers` 提示；
- `graph nodes` 的 bit node 增 `parent_bus`、`bit_range`、稳定别名。

### 接受标准

- C2 场景下，bus-level 查询能显式提示并可选展开到位选节点；
- 不改变默认输出（避免破坏现有 agent）；
- 有真实 CVA6/小 fixture 测试。

## 3. P0 — dataflow 对 bit endpoint 的语义

### 问题

driver 边存在时，`dataflow analyze lsu_vaddr_i → canonical_addr_check` 仍返回：

```text
is_reachable=false
0 paths
```

需要注意：C1 的 **bus 端点** `lsu_vaddr_i → canonical_addr_check` 返回 `false` 在
当前节点语义下是**正确**的——真实边从 `lsu_vaddr_i[63:38]` 位选节点出发，直接查该
精确 bit node 会返回 `is_reachable=true`。这里的问题是**可发现性/提示不足**，不是
把 bus 级正确结果改成 unknown。若某条查询确实因粒度不支持而无法判断，才应返回
unknown + reason。

### 候选改动

- 返回 `is_reachable=unknown` + `reason=bit_endpoint_not_supported`；
- 或明确支持 bit endpoint，并与 `drivers --bits` 对齐；
- 在文档/JSON schema 中记录端点粒度限制。

### 接受标准

- 有测试区分“确实不可达”和“当前粒度不支持”；
- agent 不会把 `false` 误读成“没有结构路径”。

## 4. P1 — evidence source location 完整性

### 问题

C1 的 `drivers --evidence` 表达式正确，但 `file=None, line=None`；无法从 evidence 回到源码。

### 候选改动

- 能从 live graph 解析 source location 时填 `file/line/column`；
- 无法解析时返回显式 `source_unavailable`，不要只给 `None`；
- 区分内存源、snapshot、历史 blob 三种情况。

### 接受标准

- C1 fixture 至少给出文件/行，或明确 `source_unavailable`；
- JSON schema 和文档同步。

## 5. P1 — bit node 可发现性与可读性

- bus result 附 `bit_nodes`；
- bit node 提供 `parent_bus` / `bit_range` / 可选短别名；
- `graph nodes --match` 支持按 parent bus 聚合；
- 文档给 agent 一条固定下钻路径。

## 6. P2 — snapshot-first / 冷启动引导

P187 实测：

```text
cold rebuild ~20–23 s
warm query 0.5–0.9 s
```

不要求改默认 cache（P182.5 已决定不做 serve/默认 cache 变更），但应在 agent 协议和 README 中明确：

```text
大项目先 snapshot save
后续查询用 --from-snapshot
```

## 7. P2 — 大项目 filelist 诊断

完整 CVA6 `Flist.cva6` 因生成文件/vendor submodule 无法直接编译。建议：

- 明确列出缺失生成文件/子模块；
- 提供项目适配说明；
- 错误信息区分“缺文件”“缺 package”“不支持语法”。

这不是 core 语义 bug，但影响真实采用。

## 8. 不建议的改动

- 不为“比 grep 快”做优化；grep 单命令与全图构建不可直接比较；
- 不把 P187 两个非盲案例当成自动发现率；
- 不因为 P187 改 shadow/cache/serve；
- 不默认把 bit 展开混入所有 bus 查询，必须显式/可选。

## 9. 建议顺序

```text
1. bit-select 查询提示/展开
2. dataflow bit endpoint 显式 unknown
3. evidence source location
4. bit node 可发现性
5. snapshot-first 文档/协议
6. filelist 诊断
```

这些是候选建议；进入实现前需在 PLAN 中登记并决定 API 形状。
