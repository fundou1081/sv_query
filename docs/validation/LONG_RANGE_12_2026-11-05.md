## 1. 协议

- **source 臂**：源码 copy 在 `/tmp/lr_pilot`，运行时全局 `sv_query` 二进制已临时移走；
  要求只读源码/grep，最多 8 次工具调用。
- **svq 臂**：同一源码 copy，`sv_query` 可用；其余条件相同。
- 每题要求 exact canonical ID / path / count；
  评分脚本确定性比较，不调用模型。
- 12 题 × 2 模型 × 2 臂 = **48 个 agent**。

## 4. 典型错误

### source-only

- AXI：把 `axi_adapter.m_axi_araddr` 的父端口连接误算成 driver，或把 load 判空。
- SERV：把 **terminal fanout** 当成 direct fanout（12 vs 8）；
  把 `serv_rf_top.cpu` 实例节点当成 path 节点；
  漏掉/误加 generate 内的 CSR。
- Pico：ID 写成 `file:line`；把 `picorv32_core.mem_valid` 当成 adapter 的直接 driver；
  把 `xfer_done` 的 6 个 canonical load 按源码行拆成 7 个。

### 一个被审计掉的假失败

首次 T2 结果里，`picorv32_axi.axi_adapter.mem_rdata[16]` 被报成
`bit_base_fallback`/count=0。复验发现：agent 把 AXI/SERV/Pico 混在
`full.f` 里查询，图的根/bit 节点选择变了。

用任务规定的单文件输入 `--file pico/picorv32.v` 重跑后，两个模型都返回
正确的 `...mem_axi_rdata[16]`。因此这不是 CLI bit fallback 已知缺陷，
而是**任务输入污染**；已写入复验脚本的约束。

## 5. 成本（token / tool calls / wall time）

从 DSH 子 session 的 `tokenUsage` 提取；总输入 = uncached + cacheRead。

| 模型 / 臂 | mean total tokens | tool calls | tokens / correct | mean wall |
|---|---:|---:|---:|---:|
| MiniMax source | 237.6k | 15.2 | 407.4k | 51.4 s |
| MiniMax svq | 329.7k | 18.4 | 329.7k | 130.6 s |
| DeepSeek source | 123.2k | 8.3 | 246.4k | 57.2 s |
| DeepSeek svq | 244.2k | 12.0 | 244.2k | 74.9 s |

结论更精确：

- `svq` 总 token 反而更高（尤其 MiniMax）；
- 但 **tokens per correct** 在 MiniMax 上更好（407k → 330k），
  DeepSeek 基本持平（246k → 244k）；
- wall time 仍然更高，原因包括 cold build 和额外验证查询；
- 没有拆分 cold build / warm query，也没有价格换算。

**不能把 wall time 或 token 总量单独当作成本结论。**

## 6. 可信度

支持：

- 在这 12 题上，sv_query 臂把 exact 准确率从 **6–7/12** 提升到 **12/12**；
- 两个模型都给出一致的、可核对的 canonical ID/path；
- 工具减少了“源码上找错端口/把 terminal fanout 当 direct”的错误。

不支持：

- “准确率提升 X%”的总体结论（12 题、单 seed、任务手工挑选）；
- “成本更低”；
- “模型能力排名”；
- HWE-Bench/VeriBugBench 或修复任务结论。

## 7. 仍然存在的实验缺陷

1. **source 臂仍不干净**：即使二进制移走，MiniMax 的某些输出仍引用了
   `/Users/fundou/my_dv_proj/sv_query` 里的 `connection_extractor.py` 规则。
   它不是纯“只有源码”的控制组。
2. **token/tool-call 来自 DSH session 日志**：已补，但未做价格换算/cold-warm 拆分。
3. **单 seed**：无重复运行。
4. **bit 失败已审计**：首次结果的 bit fallback 来自混合 filelist，
   单文件重跑正确；复验脚本必须检查任务输入是否被混用。
5. **Ground truth 非双盲**：由源码 + sv_query 双来源建立。
6. **任务难度不均**：AXI 对 MiniMax source 很容易，SERV/Pico 更能区分。

## 8. 结论

这轮比 4-task pilot 更清楚：

> **sv_query 的主要价值是减少结构事实错误和模型间差异，而不是降低单次调用时间。**
> 两个模型带工具后都达到 12/12；agent 的验证行为仍会把 wall time 拉长。

在完成 token/tool-call 计量、真正隔离 source、并做多 seed 前，这仍是
**内部验证**，不应写进对外性能/能力声明。
