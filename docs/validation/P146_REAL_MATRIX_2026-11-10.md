## 4.1 迟到的 UART worker：BLOCK 的两个真实缺陷

UART worker 在 P146 完成后返回，发现两个 blocker：

| ID | 问题 | 处理 |
|---|---|---|
| B1 | `dataflow analyze` 把 BIT_SELECT parent 当成目标，返回 `is_reachable:true` 但路径最后不是请求 dst | 已修：`DataFlowGraph.analyze` 过滤 `p[-1] == to_signal` |
| B2 | 默认无向 `paths --canonical` 在 UART 4.8k 节点上可无限运行 | CLI 增加 `--max-depth`，默认 50；UART 实测 ~6s |
| M1 | dataflow path 端点污染随 max_paths 放大 | 随 B1 端点过滤修复 |
| M2 | `verify claim` 未请求 bidirectional 时 reason 仍写 reverse=True | 已修：未请求时 reverse=None，reason 只报 forward |
| M3 | frontier probes 对 snapshot-only 的 connections/instances/ports 不可执行 | 已记录为 CLI 能力缺口，probe 本身指针正确 |

回归测试：
