# P127 两个新增 DV-derived 任务

**日期**: 2026-11-09
**来源**: OpenTitan UART `tx_overide` + I2C `host_error_intr`
**结果**: 初次 2/4；修正 T1 alias schema 后 **4/4**，0 false-confident/false-found

---

## 1. 任务

### T1 UART TX override discovery

从 UART testplan `tx_overide` 提取。

问题不给 canonical id，要求代理找出：

- OVRD enable / value；
- TX flop；
- TX pin；
- priority；
- OVRD value → TX pin 的 canonical path。

### T2 I2C SDA interference path

从 I2C testplan `host_error_intr` 提取。

要求 `i2c.cio_sda_i -> i2c.i2c_core.event_sda_interference` 的 13-hop canonical path。

## 2. 初次结果

| task | MiniMax | DeepSeek |
|---|---|---|
| UART TX override | ❌ high-confidence | ❌ high-confidence |
| I2C SDA interference | ✅ | ✅ |

```text
2/4 exact
2 false-confident
```

### T1 失败原因：不是推理错，是 ID alias 歧义

两个模型都返回：

```text
uart.uart_core.ovrd_tx_en
uart.uart_core.ovrd_tx_val
```

而 ground truth 要求：

```text
uart.uart_core.reg2hw.ovrd.txen.q
uart.uart_core.reg2hw.ovrd.txval.q
```

两者都是真实 canonical 节点。  
MiniMax 的 path 正确；DeepSeek 从 alias 根开始，路径 4 而非 5。

题目没有 pin 住 “register-side canonical id / path root”，所以这是 **task schema 歧义**，不是模型能力失败。

## 3. Schema 修正后复测

T1 明确要求：

```text
只接受 uart.uart_core.reg2hw.ovrd.*
path 必须从 reg2hw.ovrd.txval.q 开始
alias 不接受
```

复测：

| 模型 | exact | 时间 | calls |
|---|---|---:|---:|
| MiniMax | ✅ | 38.5s | 20 |
| DeepSeek | ✅ | 34.0s | 18 |

合并 T2：

```text
4/4 exact
0 false-confident
0 false-found
```

## 4. 结论

```text
两个新增任务最终都通过；
T1 的初败暴露的是 alias/root schema 问题；
不是 discovery 失败。
```

同时说明：

- discovery 任务必须 pin 住 register-side vs alias；
- path 任务必须 pin canonical root；
- 否则“canonical”会有多个合法答案。

## 5. 边界

- 2 个任务，仍只有 UART/I2C；
- 初次 run 与 schema retry 是分段结果；
- ground truth 仍由同一团队 source 审阅 + CLI 交叉确认；
- 不是用户研究；
- 不是 fault localization / patch。

## 6. 决策

```text
不因 alias 歧义加 tool alias-canonicalization 功能；
先要求 intake schema pin canonical root。
只有当真实任务反复出现 alias 选择问题时，才考虑工具层 canonical alias 解析。
```
