# P134 real-use pilot：3 个场景

**日期**: 2026-11-09
**执行**: worker 独立扮演验证工程师，使用 CLI
**结果**: 2 个场景主链可用；发现 1 个 blocker、4 个 friction

---

## 1. 场景

### S1 random → constraint → RTL

I2C `i2c_item.rcont`：

- `trace constraints` 正确抓到 `rcont_c`：
  - `vars=[rcont, stop]`
  - `conditions=[i2c_item.read]`
- `constraint-neighborhood` 一次返回 `{rcont, read, stop}`。
- RTL 侧：
  ```text
  reg2hw.fdata.nakok.q
  -> fmt_fifo_wdata[12]
  -> u_fifos.fmt_fifo_wdata_i[12]
  ```
- **失败点**：跨 FIFO 后没有回连：
  - `paths nakok.q -> fmt_flag_nak_ok` = not found
  - `drivers(fmt_fifo_wdata)` = 0
  - `loads(nakok.q)` = 5，但只有 bit-select 边
  - 必须读 RTL 才知道 FIFO 读侧关系

### S2 verify（含 unknown）

I2C 4 个 claim：

| claim | status |
|---|---|
| `fmt_fifo_rdata[12] -> controller_fsm.fmt_flag_nak_ok_i` | **verified** |
| `nakok.q -> fmt_fifo_wdata` | **contradicted** |
| 不存在信号 typo | **unknown** |
| 反向 path | **contradicted** |

结论：verify 状态保真，unknown 没有退化成成功；counterevidence 指向 S1 的孤儿总线。

## 3. 已修：architecture --json --svg

原因：

```python
if json_output:
    emit_json(...)
    return   # 吞掉后续 svg/dot 写出
```

修复：

- 不再提前 return；
- JSON 先输出，然后仍写 DOT/SVG；
- JSON 模式不污染 stdout（不打印 “wrote…”）；
- 增加 `--json --svg` 回归测试（3 tests passed）。
