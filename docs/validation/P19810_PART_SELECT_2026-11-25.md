# P198.10 part-select investigation (2026-11-25)

> **Status**: investigation complete; fix not applied. P198.10 remains open.

## Observed behavior

| RTL | Result |
|---|---|
| `assign {y1,y0} = {a[4:1]};` (descending, legal) | per-bit edges `a[2:1]→y0`, `a[4:3]→y1`, refs present |
| `assign {y1,y0} = {a[2:5]};` (ascending, legal) | segment edges `a[4:5]→y0`, `a[2:3]→y1` (declared direction preserved) |
| `assign y0 = a[2:5];` (ascending, truncating) | aggregate `a[2:5]→y0` remains; bit queries stay coarse |
| `assign {y1,y0} = {a[1:4]};` (reversed/invalid) | no edges, no unknown; pyslang returns InvalidExpression and the assignment is skipped |

## Why no ad-hoc fix

- Invalid/reversed selects never reach `_assignment_parts`; the adapter does not
  expose the assignment. The correct source is the compiler/elaboration error
  channel, not a graph post-pass guess.
- Ascending packed ranges require direction-aware source/destination bit mapping.
  P198.8's little-endian expectation was corrected: `{y[0:3]}={a[0:1],b[0:1]}`
  maps `a[0:1]→y[0:1]`, `b[0:1]→y[2:3]`, bits `a0→y0,a1→y1,b0→y2,b1→y3`.
  Direction-aware slice expansion is now in place; query authority (removing
  aggregate/coarse fanin) remains 10c.
- Removing the aggregate driver after bit expansion needs a query-level contract
  change: “bit edges replace aggregate” must hold for fanin, fanout, paths and
  dataflow, not just one expansion pass.

## Required split

1. **P198.10a** — surface invalid select/part-select from semantic diagnostics as
   explicit `invalid_part_select` unknown (no silent skip).
2. **P198.10b** — direction-aware bit expansion for ascending `[lo:hi]` and
   truncating part-select; preserve descending behavior.
3. **P198.10c** — define aggregate-vs-bit authority for fanin/fanout/paths and
   remove coarse duplicates only when bit coverage is complete.

No claim is marked verified; P198.10 stays open.
