# P165.4 filelist dependency closure

**日期**: 2026-11-12
**状态**: ✅ 第一版完成（OpenTitan adapter）

## 1. 问题

OpenTitan 的 UART/I2C/SPI filelist 依赖闭包此前是人工整理：

```text
.core → 人工选 depend / package / prim mapping / incdir → 4 轮补文件
```

`.core` 的 `depend` 是 superset，且 prim 库按工艺 split（`prim_generic` /
`prim_asap7` / `prim_xilinx`）；直接 `find hw/ip/prim -name '*.sv'` 无法 elaborate。

## 2. 实现

新增（**tools 层，不进 query core**）：

```text
tools/agent/filelist_closure.py
tools/agent/filelist_profiles/opentitan_{uart,i2c,spi_host}.json
```

能力：

- 解析 CAPI=2 `.core`，按 target fileset 递归 `depend`；
- 应用 core `mapping` / profile mapping（默认 `prim_generic`）；
- 排除 include-only header（`.svh`/`.vh` 只进 incdir）；
- profile exclude/include/incdirs；
- 复用现有 `filelist prune --top`（保守 top-reachable）；
- 输出 `+incdir+` + compile files。

命令：

```bash
python3 tools/agent/filelist_closure.py \
  --root ~/my_dv_proj/openrtl/opentitan \
  --core hw/ip/uart/uart.core \
  --profile tools/agent/filelist_profiles/opentitan_uart.json \
  --prune-top uart \
  --output /tmp/uart_closure.f --json
```

## 3. 真实项目验证

本机 OpenTitan HEAD `a82c489`（浅克隆，仅作 source root）。

```bash
# 生成
python3 tools/agent/filelist_closure.py --root ... --core hw/ip/uart/uart.core \
  --profile tools/agent/filelist_profiles/opentitan_uart.json \
  --prune-top uart --output /tmp/uart_closure.f --json

# 验证
SVQ_SNAPSHOT_DIR=/tmp/uart_closure_snap \
```

## 5. 边界（仍未宣称）

- 这是 **OpenTitan adapter**，不是通用 `.core` 标准实现；
- profile 仍需要项目特定的 mapping/exclude/incdir；
- 依赖 PyYAML；
- 生成的是候选 filelist，**必须**再跑 `snapshot save` 证明 0 elaboration errors；
- 未把 OpenTitan source 或 snapshot 固化进 repo（体积/许可/可复现策略未拍板）。

因此 `KNOWN_LIMITATIONS §3.11` 从"全手工"降为"有自动化工具，但仍需 profile 与外部 source root"。
