## 为什么取消这一层

exp 当初的定位是"降级区"：能力先放进来，靠真实项目慢慢验证，达标再转正。
实际运行下来，这一层**没有一条完成转正**：

- 没有真实项目验证（只有 fixture 与 demo）
- 没有锁定的判定语义（同一输入的解释不稳定）
- 没有写清失效场景

留着它的代价是实实在在的：使用者会以为可用（而输出可能是错的），
agent 会在 `capabilities --include-exp` 里看到 24 个"看起来能用"的工具。

方豆决定（2026-10-20）：**整体退役**，想法留档，将来逐个重新设计。
